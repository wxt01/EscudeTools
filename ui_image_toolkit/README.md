# ui_image_toolkit · 游戏 UI 图片文字汉化子工具

> 本仓库主管线（解包 → 解脚本 → 翻译 → 字库 → 回封）见根目录 `README.md`。
> 本模块是**独立子管线**，只处理「文字直接烧在 PNG 里」的界面图：
> 图片从 `gfx` 解包产物直接处理，成品随 `gfx.bin` 回封，不经过译文数据库。

## 一、和 `scripts/ui_*.py` 怎么分工

仓库里还有一批 `scripts/ui_*.py`（`ui_image_patch.py`、`ui_inpaint_patch.py` 等），
两者不是重复实现，是两条路线：

| | `scripts/ui_*.py` | `ui_image_toolkit/` |
|---|---|---|
| 定位 | 自动化批量替换尝试（两套可用、三套失败记录，见 `docs/05`） | 逐图人工精修管线 |
| 适用 | 纯色底、简单竖向渐变、底板能自动重建 | 多状态图、发光字、木牌/胶带/纸片等复杂底板、有禁改装饰 |
| 几何 | 脚本内启发式推断 | 每张图**实测**后写进 `config_batchN.py` |
| 验收 | 目视 | 自检脚本 + 坏稿探针 + 对照图 + 成品 md5 同源 |

判据在 `docs/05-界面图汉化.md` 第一节：**文字区域的底色能不能无损重建**。
能，走自动化；不能或需要三态逐像素一致，走本模块。

## 二、目录约定（2026-11-09 起）

脚本与数据目录**同级**，全部 `config_*.py` 的 `ROOT` 就是本目录：

| 目录 | 用途 | 入库 |
|---|---|---|
| `待做原图/` | 主对话放进来待处理的日文原版图 | 仅 `.gitkeep` |
| `待交付/` | 成品 + 对照图，等主对话验收入库 | 仅 `.gitkeep` |
| `工作输出/` | npy 掩码、诊断图、临时对照 | ❌ gitignore |
| `交付归档/` | 历史任务说明（`任务说明_历史.md`）与旧成品 | ❌ gitignore |
| `探索脚本/` | 一次性探针 | ❌ gitignore |
| `回归基准/` | 调试用差异样本，不是必须命中的基准 | ❌ gitignore |

`SRC_DIR` → `待做原图/`，`DST_DIR` → `待交付/`，`WORK_DIR` → `工作输出/`。
**不要再把 `ROOT` 写成 `HERE.parent`**：那会指到仓库根 `11_工具合集/`，
所有路径都会落空（2026-11-09 修过一次）。

## 三、四件套：每批图一组脚本

| 文件 | 作用 |
|---|---|
| `config_batchN.py` | 几何、译名、字色、样式——**改配置优先改这里** |
| `build_batchN.py` | 生成成品 |
| `verify_batchN.py` | 自检：允许窗口外 0 改动 / 旧字墨迹已擦除 / 逐格有中文 / 装饰逐像素保留 |
| `compare_batchN.py` | 分组对照图 + 成品 md5 前后同源校验 |
| `_badprobeN.py` | 坏稿探针：故意把中文抹回英文，确认自检拦得住 |

通用底座：`repair.py`（三种补底）、`inspect_sprite.py`（结构诊断）、
`layout.py`（墨迹对齐量法）、`build_batch4.py`（字体/判据/补底函数，后续批次复用）。
`config.py` / `build2.py` 是第一批的单图 worked example，**几何参数勿照抄**。

依赖 `Python 3 + numpy + Pillow + 一个中文字体`（STSONG / simsun，config 内有跨平台候选）。
**不需要 cv2**。

## 四、接手新图的标准流程

1. 主对话把原图放进 `待做原图/`，并给出译文定稿。
2. **增量修改一律以最新已汉化版为底图**，不是游戏原版。
3. 侦察：尺寸/通道 → alpha 分层 → 逐格底板与字色 → 多状态差分 → 圈出禁改装饰。
4. 新建 `config_batchN.py`，所有坐标颜色字号从文件实测，不抄文档估算值。
5. `build → verify → _badprobe → compare` 全绿，再放大与 1:1 各看一遍。
6. 成品与对照图放 `待交付/`，由主对话验收、入库、打包。

**同名注意**：`config` / `chart` / `file` 三个游戏目录都有 `parts.png`。
工作文件用 `config_parts.png`、`chart_parts.png`、`file_parts.png` 这类前缀区分，
交付时按主对话要求改回原名。
