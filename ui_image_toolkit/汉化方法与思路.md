# 标题按钮汉化：方法、思路与工具说明

> 写给下一个接手这类工作的人或 AI。**这不是照着跑就能复现成品的构建公式**——
> 脚本里的坐标、颜色、字号、阈值只对本项目这几张图成立，换图必须重新量。
> 能带走的是：拿到陌生游戏 UI 雪碧图时，怎么在几分钟内判明结构、选对工艺、
> 避开已验证的坑，并在出问题时快速定位与回退。
>
> 全文三层：**第 0 节**是决策卡，动手前读完即可；**第 1~2 节**是可迁移的方法与工具；
> **第 3~4 节**是三组案例与返工索引，对号入座时再查。
>
> **方法和答案要分开带走。** 三组图的结论有互相冲突之处（对齐方式、要不要补底、
> 辉光范围），那不是文档自相矛盾，是图的结构不同。先按 1.1 判明属于哪一类，
> 再挑路线。脚本里所有数字都是这三组图的答案，不是这类题的公式。

## 0. 三分钟决策卡（先读这个，别先读脚本）

### 0.1 五个问题，问完再动手

| | 问什么 | 怎么量 | 结论指向 |
|---|---|---|---|
| Q1 | 文字背后是透明还是实心底板？ | 看**格间空列**和**原本没字的格**在文字高度的 alpha | ≈0 → A 透明；>200 → B 有底板；中间值先确认是不是半透明面板（3.3） |
| Q2 | 有没有独立的装饰资产？ | 笔触、照片、边框、箭头、滑块、黑框 | 有 → 先把「绝对不能碰」的区域写成配置，逐像素核对（3.3） |
| Q3 | **同一行里每格的底色和字色一致吗？** | 逐格算底板 RGB 中位数、文字主色 | 不一致 → 必须逐格量，**绝不按行号写死颜色**（4.3，本项目最贵的坑） |
| Q4 | 原文字怎么对齐？ | 量各格右沿 / 左沿 / 中心哪个恒定 | 照抄：右沿恒定→右对齐；中心恒定→按墨迹中心居中；左沿恒定→左对齐（1.1、3.1） |
| Q5 | 原文字的发光是什么形状？ | 量字上下的 alpha 剖面 | 只有笔画外 1~3px 有光→贴笔画紧光；字外 10px 仍有 alpha 15~50→整片柔光雾，要字形外扩 + 大半径模糊 |

**Q3 单独强调**：`button.png` 第三行前 9 格是橙黄底深红字，第 10 格却是青绿底白字。
按「第三行 = 深红字」写阈值，那一格白英文一个像素都没擦掉，中文还被染成红色。
用户一句「英文没删干净就加了中文」把两个症状一起点破。

### 0.2 按结构选工艺

| 结构 | 擦旧字 | 回填 | 重画 |
|---|---|---|---|
| A 透明底 / 发光字 | 整块清成 alpha=0（连辉光一起） | 不需要 | 白字 + 下层描边 + 按 Q5 选辉光；字核心要挖空免得被染成光色。**斜体艺术字是例外**，层序与字体族按 4.1 重判 |
| B 实心做旧纹理（按钮） | **逐格**以「与该格底板中位色的差异」找文字，膨胀盖住描边/投影 | `patch_repair`：同格干净样本回填，低频取每列中位色、高频取真实残差 | 中文用从该格量到的字色 |
| B 有渐变 / 木纹（木牌） | 同上，mask 保持碎片状，别连成一大片 | `diffuse_repair` 归一化卷积低频 / 或 inpaint；本项目木牌最后也用了同格回填 | 同上 |
| C 透明叠加层（框架图） | 只把文字带清成 alpha=0 | 不需要 | 白字 + 青光；装饰笔触带原样保留 |

**别把 A 的「整块清除」套到 B 上，也别把 B 的「补真实纹理」套到 A 上。**
补底三种已验证的失败模式：填常量色 → 假底板；低频取全图均值 → 偏亮/偏暗补丁；
平移借用别处高频残差 → 把其它格的字母虚影搬进来（1.3）。

### 0.3 症状速查：用户抱怨 → 大概率原因

| 听到的反馈 | 先查什么 | 详见 |
|---|---|---|
| 「像用亮色把字涂掉了」/「字后面有亮牌色板」/「有字形负影、暗矩形」 | 把旧字笔画填成背景色、凭空造底板；补底填常量或全图均值；顺字形做距离场清除；辉光线性铺开 | 1.3、4.1 |
| 「英文没删干净就加了中文」/「这个字不该是红色」 | 按行号假设字色、阈值只认一种颜色，漏了异色格；中文色也没逐格量 | 4.3 |
| 「多了原版没有的线 / 装饰」 | 把发光下沿误判成装饰；任何「原图有 XX 装饰」都要有 alpha 剖面证据 | 4.5 |
| 「位置很怪 / 字被切掉」/「这个词靠左、居中没对上」 | 没量原图对齐方式就顺手居中；或按词格几何中心居中，没量原字墨迹中心 | 1.1、4.1 |
| 「字太大 / 太白 / 发虚」 | 只盯放大图调参，没回 1:1；复杂字抗锯齿发虚与基线错位是两回事 | 1.5 |
| 「汉化后有残留空行 / 某状态没字」 | `cy` 是绝对 y 还是行内相对 y 混了；自检没按行分别数像素 | 1.5 |
| 「中文发灰 / 比原字暗一档」 | 宋体细横在小字号下抗锯齿把中间调拉低，白字实像素只有原图 1/5 | 1.4 |
| 「又是色板，每个词后面一块」/「字周围一圈灰板、彩色杂点」 | 汉字是方块字：MaxFilter 外扩、描边、宽辉光填满字间；整层 RGBA 旋转串色；柔光模糊后乘高 gain 饱和 | 1.3、1.4、4.1 |
| 「最后一个字被遮挡 / 串到旁边一列」/「字和旁边的词粘一起」 | 中文比原词宽，超过引擎源矩形（右沿红线 = 原图墨迹右沿）；或按词格分别裁辉光把光切断 | 1.4、4.1 |
| 「这一列不该这么亮」 | 禁用态是半透明暗字（原图 alpha 全 <100），被画成不透明实字 | 1.4 |
| 「原图是斜的，中文变正了」/「整体斜过来，你是一个个正字排阶梯」 | 逐字基线递升装斜：整行 PCA 达标但字内笔画仍水平；或只给了很小的 shear | 4.1 |
| 「字太粗，风格差很多」/「红白关系反了、白字红描边」 | 粗黑体 + 实心字身；把「最实的一层」搞错——这类图描边最实、字身半透明、柔光最淡 | 4.1 |
| 「对照图正常，成品图却没汉化」 | 成品在对照图生成后被旧稿/外部文件覆盖；自检只查「格内有亮像素」，英文原字也能通过 | 4.2 |
| 「木牌/按钮上有一块矩形补丁」/「擦字区一条条竖纹」 | 擦字 mask 膨胀过大连成整块，2D 扩散把周围暗边平均进来；逐列插值又留下列间断 | 1.3、3.5 |
| 「中文字缺上半截、像 1寸 1=3」 | 字形基线算成负 y，字的上半截被画到画布外裁掉；描边 alpha 重复乘 255 会把字染成描边色 | 3.5 |
| 「倾斜对了，但第一个字被挡住一部分」 | 左沿抄了文档估算值而非原图实测墨迹左沿；首字探进源矩形/遮罩左界 | 4.1 |
| 「还有 XX 没翻译」/「小格子里的字太大、顶到边」 | 文案清单来自文档，但图里还有清单外的英文；小格要先量格高再定字号，两行中文比塞一行更稳 | 3.6、4.6 |
| 「擦完字还剩一圈黑影」/「小格里半边深半边亮」 | 只判白字、漏了深色投影/描边；按列插值让相邻列的上下端点色差变成竖条 | 3.6 |

### 0.4 硬纪律

- **透明底绝不把旧字笔画涂成背景色**：那等于在字后造一块不透明色块，笔画越密越刺眼。
  正解是整块删除 → 实测背景重建 → 重新渲染。清除要整块且均匀，别顺字形轮廓做距离场，
  等距线会把字形「印」在背景上。
- **辉光范围照抄原图剖面**，别把「只贴笔画」当通用公式（Q5）；光层要挖空字核心，
  否则白字被染成光色。整片模糊要幂次压缩，低 alpha 不压没就会变成底板。
- **对齐照抄原图，别顺手居中，也别一律右对齐**——三组案例答案相反，都是量出来的。
  基准是**原字墨迹中心 / 墨迹左右沿**，不是词格几何中心；词格是引擎切的，与实际重心无关。
- **文字颜色、清除阈值逐格量**，别按行号或状态名假设；状态行 ≠ 统一配色。
- **先做多状态差分**：相邻状态列/行逐像素相减，文字层几乎全等就复用一套字形，
  状态差异用换辉光色表达（1.2）。
- **辉光强度按原图 alpha 分层校准**，别凭观感调 gain（1.4）。
- **验收同时看 8 倍和 1:1**：放大图找残影色块，1:1 定最终观感。
- **倾斜 = 整行渲染完对整层一次性旋转**（`rise=0`），且**只旋各层 alpha、颜色用纯色重建**。
  逐字递升 + 斜切是伪斜；整层 RGBA 旋转会串色（4.1）。
- **排版宽度按原图墨迹框**：左沿和右沿红线都从文件量，不抄文档估算值；
  超红线时按行缩字号，**四列共用一个字号**。
- **成品与对照图必须同源**：对照图从交付目录读、生成前后核 md5、刷新完立刻跑全量自检；
  自检必须含「每格旧字确已擦除」这类判据（4.2）。
- **文档给文案，文件给几何**；冲突时以文件为准，并把差异列给用户看（4.4）。
- **用户当期口述 > 任务说明 > 本手册的硬约束**。第五批就推翻了两条旧结论：
  `stand_parts` 从「左对齐」改「逐行居中」、徽标从「保留不动」改「汉化」。
  别拿文档去反驳用户，改完把新结论回写进文档（4.6）。

## 1. 方法（可迁移的部分）

### 1.1 结构诊断：两个分水岭

人眼容易把「文字的辉光」看成「一条发光底板」，尤其在放大图里又叠加了大字下缘余光。
诊断一律靠 alpha 数值。`inspect_sprite.py` 关注四组量：行数行高（`H / 状态数` 后用非透明
像素分布确认边界）、每格 x 范围（文字带内的列投影）、小字带 y 范围（逐 rel y 看全行
alpha 中位数，小字会让某段明显抬高）、状态差异（逐格数白字实像素与光色像素）。

#### 分水岭一：有没有底板

看两个位置在文字带高度上的 alpha：① 所有格子之外的**格间列**；② **原本就空白的格**。

```
行0 格间列 alpha: 中位 0 最大 97 均值 7.7      行0 空白格4/6 alpha: 最大 0
行1 格间列 alpha: 中位 0 最大 193 均值 15.9
```

中位数 0、空白格最大 0 → **没有底板**（最大值非 0 是大字下缘辉光的横向余晖，正常）。
据此选路线：

| 判据 | 结构 | 做法 |
|---|---|---|
| 格间/空白格 alpha ≈ 0 | 字与辉光悬空 | 整块清除 + 实测背景重建 + 重画 |
| 明显 >0 且横向连续成带 | 真有底板 | 保留底板，只在底板范围内替换字形；带渐变时按列插值或 inpaint |

配套辅助判据：把「字周围半透明像素」的颜色取众数，能直接量出原图辉光真实色
（本项目量到深青 `(0,120,136)` / 亮青绿 `(0,220,200)` / 红 `(240,16,0)`，比凭挑的蓝色准）。
**永远读 alpha，别看着深底预览图下结论**——合成上去的深色不是原图内容。

#### 分水岭二：原文字怎么对齐

在常态行文字带里取每格白色实像素的 x 最小/最大值，看**右沿、中心、左沿哪个恒定**。
`menu_button` 实测：

| 格 | 日文白字 x | 宽 | 右沿距格右线 | 左沿距格左线 |
|---|---|---|---|---|
| 继续游戏 | 69..172 | 104 | 4 | 4 |
| 额外剧情 | 349..411 | 63 | 4 | 4 |
| 后日谈 | 553..615 | 63 | 4 | 4 |
| 读取存档 | 661..717 | 57 | 4 | 4 |
| 更改设置 | 778..856 | 79 | 3 | 4 |
| 额外内容 | 940..982 | 43 | 3 | 4 |
| 退出游戏 | 1020..1080 | 61 | 4 | **16** |

右缩进恒 3~4px（改用「含描边、alpha>200」判据则**恒 2px**），左沿差异最大到 16px
→ **严格右对齐**。三组图的答案放在一起看：

| 图 | 原文字怎么排 | 结论 |
|---|---|---|
| `menu_button` | 日文右沿距格右线恒 2px，左沿差异很大 | 右对齐 |
| `index` / `button` | 英文词中心 ≈ 格中心 | 居中 |
| `frame_*` 设置项 | 三列中心固定 220 / 640 / 1058 | 居中于列中心 |
| `frame_manual` 键位行 | 左对齐于 x=43 / 461 / 879 | 保持左对齐 |
| `sys_quit` | 三词墨迹中心 44.5 / 129.5 / 208.0，与格中心差 3~5px | 按墨迹中心 |
| `popup_parts` | 九行四列墨迹左沿 +50~53、右沿 = 红线 | 左沿对齐到 +52 |

同一张图里不同元素可以有不同的对齐方式，关键是「跟原图一致」，不是「全图统一用一种」。
实现上**别用 `textlength` 估算**：逐字绘制带字距和描边时，理论宽度与真实外沿差 1~2px，
各格累积就对不齐。`layout.word_starts()` 先以 x=0 渲染探针图层量真实外沿，再整体平移到
`COLS[ci][1] - RIGHT_INSET`；生成与自检共用同一函数，避免坐标不一致导致残留检测误报。
右对齐后中文会往左伸，**清除区左界也要跟着中文实际左沿扩展**（`CLEAR_PAD_EXTRA`），
否则中文压在没清干净的背景上。

#### 发光剖面

把字上下 10px 的 alpha 逐行打出来。例：`index.png` 红态实测「字上 10px ≈50 /
贴近字 ≈120 / 字下 10px ≈15」，边缘模糊、没有直线 → 那是一整圈柔光，不是下划线。
剖面只有笔画外 1~3px 有值 → 紧光；字外 10px 仍有 15~50 → 柔光雾。
**同一种「发光」在不同图上可能是两种完全不同的结构，先量剖面再选实现**（4.5）。

### 1.2 多状态图第一步：差分，别逐格量

把相邻状态列/行逐像素相减：

| 图 | 差分结果 | 推论 |
|---|---|---|
| `radio_button` 三列 | 文字层 32550 像素里仅 701 不同 | 文字逐像素相同，差异只在左侧圆形图标色 |
| `check_box` 三列 | 67500 里仅 1118 不同 | 同上，差异只在方框图标 |
| `sys_quit` / `sys_back` 三行 | alpha 总和完全相同（708.0k/行），RGB 中位不同 | 同一套 alpha 场，只换辉光色 |
| `popup_parts` 四列 | 列2 vs 列3 alpha 形状 IoU 0.992；列0 vs 列1 仅 0.275 | 列2/3 近乎重复；列0 是另一套禁用态 |

于是 radio/check 一套图层复制三列、sys 一套字形按行换辉光色，只有 popup 需逐列配色。
既省事，也天然保证状态切换时字形不跳动。反过来，若差分发现**字形本身**不同
（按下态变粗、有位移），就必须逐行单独渲染并分别验收。

### 1.3 清除 / 补底 / 重画：一张失败模式表

补底只用于有底板时。三条路线（`repair.py`）按纹理类型选，别混着用：

1. **`patch_repair` 同格纹理回填（本项目最终用）**：低频取「该格每列 mask 外像素的中位色」，
   高频从该格干净像素的**真实残差**里确定性取样。适合统计平稳的做旧纹理（按钮、木牌）。
2. **`diffuse_repair` 归一化卷积低频 + 松弛**：只用 mask 外真实像素插值出局部底色，
   适合大尺度渐变、同格样本不足的底板。初值绝不能用全图均值。
3. **OpenCV inpaint（Telea，可选）**：沿等照度线推进真实纹理，细笔画干净；
   但未在本项目成品上验收，装了 cv2 也别让它自动接管。

三个要点：mask 逐格自适应（取该格底板 RGB 中位数，用「与底色绝对差之和 > 阈值」找文字，
亮字深字投影一起抓，**文字主色也从该格量**）；mask 保持碎片状，笔画之间的原始底板
是最宝贵的纹理来源，整词擦除连成片时靠 `patch_repair` 兜住；膨胀要盖住描边与抗锯齿带，
漏了会留下字形负影。`texture.py`（整行平移复制）已弃用，会在木牌上产生横向条纹。

**失败模式索引**（三批图里反复出现的，按症状归类，别再逐个试）：

| 症状 | 根因 | 正解 |
|---|---|---|
| 亮青/亮白色块，笔画越密越明显 | 悬空文字被「擦除法」填成背景色，凭空造了底板 | 整块清成 alpha=0，不擦笔画 |
| 背景过于均匀、偏亮、像一块板 | 用拟合钟形剖面反推背景 / 填常量 / 扩散初值取全图均值 | 从原图同一行、同一高度、同类区域**实测**中位数 |
| 暗矩形、日文负影 | 顺字形做连续距离场清除，等值线就是字形膨胀轮廓 | 清除区形状与字形无关，内部完全均匀，只在四周羽化 |
| 擦除区偏亮/偏暗的补丁 | 低频取全图均值；多状态图各行底色差很大 | 同格每列中位色 + 真实高频残差 |
| `TTI` 等字母虚影 | 平移借用别处高频残差，把别的格文字残差搬了进来 | 高频残差只从本格干净像素取 |
| 横向断层 | 整行用一个常量背景，忽略 y 方向辉光衰减 | 按「行 × 高度」分别取中位数 |
| 青/白/红矩形光板 | 线性叠加宽半径辉光；外扩 7px 把汉字字间填满；按词包围盒画矩形再模糊 | 模糊 alpha 做**幂次压缩**（`alpha^p`，p>1）压掉字间低值；字形外扩 + 大半径模糊让边缘跟随字形；拉字距 |
| 白字变成暗色空心字 | `PIL stroke_width=1` 在宋体小字号吃掉 1~2px 实笔画 | 描边层与实字层分开渲染，实字层盖在上面；文字层 alpha ×1.25~1.45 加实 |
| 白字被染成光色 | 发光层盖在半透明细笔画上 | `ga *= (1 - core_alpha * 0.98)` 挖空字核心 |
| 青光整个消失 / 光被切断在格边界 | 按词格分别生成 patch 并各自模糊 | 整行一个图层统一渲染、统一模糊 |
| 中文比原图暗一档 | 宋体细横抗锯齿，实像素只有原图 1/5 | 文字层 alpha 乘 1.75 再 clamp |
| 后两行整个没有字 | `cy` 绝对 y / 行内相对 y 混了，又加了一次行起点 | 统一坐标口径；自检**按行分别数像素** |
| 装饰笔触 / 箭头被蹭掉 | 允许区域向上或向左外扩 | 只向需要的一侧扩，且先量那块区域里有什么 |
| 细笔画擦完仍是黑点/网点状字影 | `patch_repair` 在细笔画上 `MinFilter(3)` 的 core 几乎为空，结尾「边界 1px 半混合」保留 50% 原字；同格样本里还混着未被 mask 覆盖的字笔画 | 用「局部背景差」只选细笔画；补底改用**不从图里搬样本**的扩散低频（`build_batch4.diffuse_texture`） |
| 暗木牌/青色笔刷上出现矩形深色补丁 | 2D 扩散把周围暗边平均进擦除区，与水平渐变对不上 | `column_fill`：按列取紧邻上下真实像素线性插值；再小半径模糊抹掉列间竖条 |
| 中文字上半截被裁 / 整字变成描边色 | 基线 `py` 为负把字画到画布外；描边 alpha 已经是 0~255 却又乘 255，淡描边变不透明盖住字身 | 绘制起点留 24px 上边距，落位交给「真渲染后量 bbox 再平移」；描边层与字层分开合成 |

### 1.4 渲染：字体、层序、辉光、倾斜、排版

#### alpha 分层校准（别凭观感调 gain）

汉字笔画密度与拉丁字母完全不同。把原图和成品在文字带的 alpha 分档打印，对齐量级：
`popup_parts` SAVE 行每格 171×36：

| | >=200 | 100~200 | 20~100 | 总和 |
|---|---|---|---|---|
| 原图列 0（禁用） | 0 | 0 | 1020 | 55.4k |
| 第一版列 0 | 541 | 55 | 45 | 146.8k |
| 原图列 1/2/3 | 283 | 527 | 687 | 183.5k |
| 第一版列 1 | 979 | 92 | 647 | 289.9k |
| 按此法校准后（列 0 / 列 1） | 0 / 473 | 0 / 513 | 619 / 59 | 55.3k / 180.8k |

这张表演示的是**校准方法**，不是要守住的恒定目标：`popup_parts` 后续为消掉柔光灰板
又压过一次中低值，最终总量低于此表（4.1）。

`sys_quit` 同理：原图每行 `>=210:864 / 140~210:984 / 60~140:2455 / 20~60:1880 / 总 708k`。
MaxFilter 外扩 + gain 0.62 做出 963k（青色矩形板），收紧后 282k（光整个消失），
定稿整行小半径模糊 + gain 1.75 得 499k，是柔和包字的一圈青光且无直边。
数字不必逐档命中，但**总和量级必须对齐**。

#### 汉字是方块字：四条约束

- **字距按图量**：一般要拉开让笔画间透出底色；MaxFilter 外扩 + 描边 + 宽辉光会把
  字间空隙填满，拉丁字母笔画稀疏同样参数不炸，中文一用就炸。但四字行受红线限制时，
  宁可收紧字距、由 `fit_sizes` 缩字号，别硬撑宽度。
- **禁用态差别常在 alpha 而非 RGB**。原图列 0 所有像素 alpha<100，
  画成 `fill=(196,179,160)` 的 alpha=255 会亮 3 倍；最终做法是整层 alpha 压到 0.42、
  `glow=0`，只留低 alpha 字身（峰值 <120）。量的时候连 alpha 一起分层。
- **字数 × 字号 < 格宽 − 余量**。`sys_quit` 格宽 83px，22px×4 字=91px 直接冲进相邻格，
  收到 19px（76px）才正常。
- **层序照原图反推，别信「字应该是实心的」**。斜体艺术字里最实的一层可能是描边
  （4.1）。字体族也是结构决策：原图是衬线斜体就用宋体（横细竖粗、末端顿角），
  粗黑体一用就毁风格；「太粗」调小字号只会让字更糊。

#### 倾斜：整层旋转，只旋 alpha

原图既有整行基线倾角，字形本身也斜。正解是**整行水平渲染完（含柔光/字身/描边三层），
对整层一次性旋转 6.5°**，`rise=0`——每个字的横竖笔画都跟着斜。
逐字基线递升 + 斜切是伪斜：整行 PCA 能到 6~8°，字内笔画仍水平，人眼一眼看穿（4.1）。
配套五点：

1. **只旋各层 alpha 灰度图，再用纯色重建合成**（`rotate_alpha` + `compose_layers`）。
   PIL 的 `rotate` 对 RGBA 逐通道独立插值、不做预乘，透明区 RGB=0 混进边缘会出暗矩形；
   「预乘→旋转→反预乘」只治暗矩形，8 倍下仍会字身灰褐、周围红绿杂点。分层旋转颜色永远干净。
2. **垂直重心校正**：绕中心旋转会让左端下沉，36px 行高里字高 23px、上下只剩 6.5px，
   左端 + 柔光会被下边界硬裁。记录旋转前 alpha 重心，旋转后平移回去（`align_patch`）。
3. **四周羽化**：上下 3px 消掉柔光被裁出的直线边；左右取 `min(3, pad-1)` 防削笔画。
4. **patch 内先右移 `render_margin=10` 再旋转**，转完把墨迹左沿补正回目标位置，
   给首字左下角的插值与柔光尾巴留空间。
5. **柔光压中低值、限上限**：`glow_gamma=1.8` 幂次压缩 + `glow_cap=190`，
   再补 `glow_fog_gain=0.16` 的极淡外雾找回白亮。整片字形模糊乘高 gain 会饱和成
   矩形灰板压住首字；本项目字区总 alpha 177k→140k，而字间空隙均值只 51.2→53.2，
   说明提亮没把板带回来。

#### 排版：从文件量「墨迹框」，自动定字号

左沿和右沿是同一个原图墨迹框的两条边，都要按文件量，别抄文档估算值。
`popup_parts` 九行右沿红线实测就是原图英文墨迹右沿：
`FLOWCHART 208 / SAVE 116 / LOAD 122 / Q.SAVE 143 / Q.LOAD 149 / CONFIG 150 /
TITLE 134 / QUIT 117 / BACK 120`（配置 `redline` 再各留 1~2px 余量）；
左沿实测 +50~53（常态列中位 52）。
四字项塞不进同样宽度时别手算：`fit_sizes` 用常态列试渲染，右沿超「红线 − 2px」就降 1px
字号再试，**四列共用一个字号**（否则切状态时字忽大忽小）。定稿
`[23,23,23,21,23,23,19,15,23]`，QUIT 行 15px 是红线逼出来的，不是没调好。

### 1.5 验收与交付安全

#### 自检口径

`verify2.py` / `verify_all.py` / `verify_batch3.py` 的核心判据，按用途挑：

| 判据 | 防什么 |
|---|---|
| 尺寸 / RGBA | 游戏能否直接读取覆盖 |
| 清除区外 0 改动（透明底图）/ 显著改动落在预期矩形内（有底板图） | 装饰、图标、大字、UI 被蹭掉 |
| 装饰资产逐像素全等（`BRUSH_BANDS`、箭头、照片框、BGM/BGV） | 允许区域外扩误伤 |
| 原图文字像素 100% 落在清除区内 | 整格漏擦 |
| 每格旧字确已擦除（`erased_check`，见 4.2） | 英文原字原封不动却「全绿」 |
| 逐格都有中文（按行分别数像素） | 漏字、某一状态没字、行内相对 y 写错 |
| 中文包围盒 / 墨迹中心 / 左右沿与原图对齐 | 位置漂移、越红线、状态切换跳动 |
| 状态梯度仍在（图标色、辉光色、亮度） | 差分复用时把状态抹平 |
| 把用户反馈固化的回归判据 | 同类问题复发（如「无实心红下划线」「禁用列无辉光」） |

三个容易写错的口径：
- 禁用行少了两格中文，**不能拿整行包围盒互比**，只能比共有格；空白格只查本格 x 范围，
  否则把相邻格的羽化余量算进来误报。
- 「格中心 ± 固定窗口」会把隔壁格的字算进来（本项目两格只隔 19px），得出假宽度；
  末尾检查应在本格右侧小区间内只取白色实像素最大 x，或直接用 `word_starts()` 的已知起点。
- **别用「成品里还有没有白字」判断残留**：中文也是纯白，笔画交叉处与原英文会巧合相同
  （radio 5.6% / check 6.4%）；清除区已清成 alpha=0，区内任何不透明像素只可能是新中文。
  同理，图标高光/箭头高光会被当成文字，阈值检查要**带 x 范围限定**，只统计文字列。
  「带外改动数」里混着新文字抗锯齿过渡（±1~16），别用「有改动」判失败，用幅度判。

#### 视觉验收

三栏对照（原图 / `clean_base.png` / 成品）最高效：底图脏 → 清除步骤的问题；
底图干净但成品怪 → 渲染参数的问题。8~16 倍找字形负影、涂抹块、矩形轮廓、断层、
辉光糊成板；**1:1 才是最终拍板**——放大会放大「字太粗太白」的错觉，也会掩盖光板。
量化指标只做前后相对比较，没有绝对及格线（成品青光弱于原图是有意收敛，不代表不合格）。

#### 交付安全：三份文件不是一份

**渲染脚本的输出、磁盘上的交付文件、对照图取样的那份文件，是三个东西。**
对照图强制从交付目录读，生成前后各记一次成品 md5，不一致直接断言失败，刷新完立刻跑
全量自检——这样「刷新对照图」一个动作同时完成同源核对与验收（事故始末见 4.2）。

### 1.6 标准工作流

```bash
cd 工具
python inspect_sprite.py --cols <格区间> --band <文字带> --rows <状态数> --out _输出/诊断
# 第一组
python build2.py && python verify2.py && python compare.py --pick 0,2,4 --scale 8
# 第二组
python build_pages.py && python build_frames.py && python verify_all.py
python compare_pages.py && python compare_frames.py
# 第三组
python build_batch3.py && python verify_batch3.py && python compare_batch3.py
```

`inspect_sprite.py` 不给 `--cols` 时只做全图剖面并打印非透明连续段，适合还没定位格子的阶段。
顺序建议：**先让无字底图干净 → 再让中文白字清晰 → 最后调辉光**，一次只改一类参数，
否则出问题分不清是谁造成的。每改一次：8~16 倍确认无残影色块 → 1:1 看整体是否协调。
刷新对照图用工作区的 `refresh_compare.py`（会同时核 md5 同源 + 跑全量自检，非工具包必需件）。

常见变体：状态数不是 4 时字典长度与「逐行递增」断言跟着改；换平台补
`config.find_font()` 后几乎一定要重调字号/字距/加实系数；索引色 PNG 先 `convert("RGBA")`；
文字带与大字在 y 上重叠时不能简单下移 `BAND_TOP`，需按格局部清除或从相邻状态行借背景。

**这些脚本是「能跑的示例实现」，不是必须照抄的框架。** 路径基于 `__file__` 相对推导，
整个文件夹拷走能直接跑（字体除外，见 `config.find_font()`）。接手新图更常见的用法是

`_输出/回归基准/` 是**调试用的差异对照样本**：改动参数后看差异落在哪几行几列，

探索期的一次性脚本（`analyze*.py`、`diag.py`、`preview.py`、被推翻的 v1 `build.py`）
**没有收进工具包**：做法已被证伪，留着容易被误用。有用的部分已整合进
`inspect_sprite.py` / `compare.py`，失败方案连同原因写在 1.3 与 4 节——那部分比旧代码更有价值。

### 3.2 第一组：`menu_button.png`

1092×244 RGBA，4 行状态 × 7 列，行高 61；每格上方英文大字 + 下方一行日文小字；
禁用行 CONFIG / QUIT 两格**本来就没有小字**，必须保持全透明。只换日文小字，
其余逐像素不变。文案见根目录 `任务说明.md`。四行差别实测是亮度/色相/辉光强度，
不是字形不同 → 复用同一套字形与位置，只切样式参数，状态切换时文字不跳动。

最终数据流：

```
原图 RGBA
 ├ 1 整块清除：[min(x0-14, 中文左沿-8), x1+15] × 行内 rel 31..60
 │    左右 9px 线性羽化，上下按辉光衰减给权重，内部 keep=0
 ├ 2 背景重建：对每个 (状态行, 行内高度 rel) 取非小字列像素 RGBA 中位数，
 │    按 keep 线性混合 → clean_base.png（单独留档）
 ├ 3 重画：冷白字 + 1px 深青描边 + 统一基线 + 字距 + 右对齐到日文末尾；
 │    两层外发光（近亮远淡，模糊 alpha 幂次压缩），文字层 alpha ×1.35 补实；
 │    win 窗口裁到 rel 30..60，上下羽化
 └ 4 alpha_composite：底图 → 辉光 → 文字（文字最后叠，白笔画不被染青）
```

## 4. 返工索引：按根因查，别按时间查

### 4.1 斜体艺术字（`popup_parts`）：模型选错，不是调参能救的

三轮反馈指向同一类盲区：**前面把颜色和位置量得很细，却把字形、层序、重心交给直觉。**

**先量，四个数字把争论变成事实**（原图 vs 返工前）：

| 量什么 | 怎么量 | 原图 | 返工前 |
|---|---|---|---|
| 整行基线倾角 | 墨迹像素加权 PCA 取主轴 | −5.4° ~ −7.0° | −0.4° ~ −2.1° |
| 字形斜度 | 逐行墨迹质心对 y 拟合 `dx/dy` | −1.77 | −0.20 |
| 笔画实度 | alpha>200 像素数（SAVE 行每列） | 289 | 901（3 倍） |
| 柔光面积 | 30<alpha<120 像素数 | 675 | 91 |
| 每词墨迹中心 | alpha>180 包围盒中心 | 44.5 / 129.5 / 208.0 | 41.5 / 124.5 / 207.0 |

`dx/dy = −0.20` 是关键：配置里明明写了 `shear=0.16`，中文方块字轻微斜切视觉上几乎
读不出来。**「代码里有倾斜」不等于「看起来是斜的」**，要用原图和成品的同一个量做差。

**四条决策，都不是调参：**

1. **倾斜用整层一次性旋转**（1.4）。先试过「逐字基线递升 `rise` + 整层斜切 `shear`」，
   PCA 也能到 −5.2°~−9.7°，但用户一句话点破：「原图的字都是整体的，斜着也是整体斜过来，
   你是每个字都是正的，通过调整每个字的高度来达到看起来斜着的效果」。
   **整行 PCA 达标不等于字内笔画也斜。**
2. **换字体族，不是换字号**。粗黑体 → 常规黑体 → 宋体做同参数并排图，
   宋体的横细竖粗、末端顿角明显最贴衬线斜体。换字体后要**重新扫描**柔光参数，
   沿用黑体的 gain 会整体偏淡。
3. **层序反推**：原图高 alpha 的 289 个像素是**描边**（列1 深褐 / 列2 红 / 列3 橙红），
   字身是 120~200 半透明暖白，柔光最淡但面积最大。旧版把字身画成 255 实心、描边做粗、
   柔光几乎没有，红白观感整个反过来。改成「柔光 → 半透明字身 → 1px 细描边」；
   常态描边色也从自定 `(36,22,24)` 换成原图实测中位 `(69,55,52)`。
4. **对齐基准换成墨迹中心**：config 直接写逐格量出的 `centers=[44.5,129.5,208.0]`，
   `x = center - tw/2`，修完误差 0 / −0.5 / −2px。复核时**按 x 投影找连通块算中心**，
   别用整格 min/max——相邻词右沿溢出 0.5px 就会测出「偏左 13.5px」的假象。

**第三轮：「倾斜对了，但第一个字被遮挡」。** 逐格检查 patch 四边，实笔画（alpha>120）
落在边界外 2px 的像素数是 **0**——笔画根本没被切掉，「遮挡」是三件事叠出来的观感：

- **位置真的错了（根因）**：任务说明写「列起点 +46」，实测原图九行四列英文墨迹左沿
  稳定 **+50~53**（中位 52），右沿又几乎正好等于红线 → 原图字框是 `[52, 红线]`，
  我们画成 `[46, 红线]`，首字左探 6px 进源矩形/遮罩左界，字宽还多 6px 逼得四字行
  再缩 1px。改成 +52 后首字落回原图字框，`pad` 从 1~4 变 7~10，旋转余量自然够，
  **清除区一点不用动**；自检加「中文左沿与原图英文左沿逐格一致（±3px）」防回归。
  曾想左扩清除区 4px 腾空间，「红色箭头逐像素保留」立刻 FAIL——箭头一直延伸到相对 43。
  **任何「腾空间」的改动都要先量那块区域里有什么。**
- **整层 RGBA 旋转串色**：8 倍下字身灰褐、周围红绿杂点；改分层只旋 alpha 后，
  字间空隙 RGB 从 `[196,182,161]` 回到 `[209,196,173]`，杂点消失。
- **柔光饱和成矩形灰板**：板的左沿正好压首字；`glow_gamma` + `glow_cap` 压中低值后消失。

**校准节奏**：先固定结构（层序、字体、倾斜方式），再对 `glow_blur / glow_gain /
body_gain` 做小网格扫描，用「核心 / 中层 / 光晕 / 总 alpha」四档相对误差打分挑最优。
三个走不通的弯路：「字形外扩环 × gain」凑面积 → 环饱和成不透明片（`>200` 从 289 飙到
1067）；单一 2px 小半径躲裁切 → 不裁了但总 alpha 只有 150k（原图 183k）；
紧光 + 大半径外雾 → 亮度补过头、雾又回来。最后**保留用户已认可的柔光强度参数**
（`glow_blur=5.0 / glow_gain=2.8`，不再靠缩小半径躲裁切），裁切改由垂直重心校正与
上下羽化解决，成板则由幂次压缩 + 上限解决，并补 `glow_fog_gain=0.16` 的极淡外雾
找回白亮——**三件事分开处理，别用一个参数同时救三个症状**。

**结果与残留**：九行左沿 52±2、右沿全 ≤ 红线、倾角 6.5° 整层旋转；禁用态峰值 115
（原图全 <120）；自检 41 项全绿，橙红箭头与 y≥400 UI 逐像素保留。最终为消掉柔光灰板
压过中低值，字区总 alpha 从 177k 降到约 140k，低于原图 183k —— **这是有意的取舍，
不是没调到位**；柔光形状不可能与拉丁字逐像素相同，那是字形差异，别再靠加 gain 去追。

### 4.2 交付事故：对照图正常，成品图却「没汉化」

列 1/2/3 的 alpha 总和 `183482 / 183485 / 183485` 与原图**逐像素完全相同**，
深底放大一看后三列还是 `FLOWCHART / SAVE / LOAD ...`；③ 找旧稿来历，
`任务说明.md` 里还留着更早一版「第 1 列中文保留、第 2/3/4 列重做」的中间状态。
**任务说明按轮次追加，旧段落描述的不是当前成品状态**，别拿它当验收依据。

为什么当时的 30 项自检没拦住：`coverage_check` 只验证清除区范围是否盖住旧字，
`every_cell_check` 只验证格内有没有 `alpha>60` 像素——原英文两样都满足；
更根本的是覆盖发生在最后一次自检**之后**，再好的自检不跑也等于没有。

补的判据 `erased_check`（无歧义、可迁移）：清除区内原图 `alpha>150` 的实笔画，
若在成品里 RGBA 逐像素完全相同，就说明这格根本没被重写。中文白字与英文白字偶发巧合
相同，实测每格 `2.0% ~ 10.9%`；完全没汉化是 `100%`。按**逐格保留率 > 15%** 判失败，
不必苛刻要求 0%。拿旧稿做探针：`FAIL 最差保留率 100.0%`、退出码 1；重建后 0.0%，全绿。

流程防护（`refresh_compare.py`）：对照图强制从交付目录读，生成前后各记一次五张成品
md5，不一致直接断言失败，刷新完立刻跑全量自检；同时不再断言「目录恰好 11 张」——
用户会自己放试验稿/备份进去，只校验必需件齐全。

### 4.3 按行号假设颜色：两个症状，一个原因

用户原话：「`button.png` 第三个应用并不是红色的字，而且你英文也没有删干净就加了中文」。
当时把第三行当「橙黄底 + 深红字」，阈值写成 `R > G*1.55 且 G < 135`；
但该行第 10 格 SETTING 是**青绿底 + 白字**，一个像素都不满足条件 → 英文完整保留，
红色中文直接叠在 SETTING 上。

正解：**逐格**取该格文字带 RGB 中位数当底板色，用「与底色绝对差之和 > 阈值」找文字
（亮字深字都能抓），再从「差异最大的那部分像素」中位数取文字主色给中文用。
**状态行 ≠ 统一配色**：特例按钮（确认/应用/返回）、禁用态、选中态都可能在同行换皮。
任何「第 N 行一定是 X 色」的假设都要先逐格打印中位数验证；自检也要**逐格**确认
原文字像素确实被改动过，不能只查「整图有没有字」。

### 4.4 文档与文件冲突：以文件为准

`任务说明.md` 是**追加式**的，接手时先读完（尤其末尾追加章节），确认范围、
定稿译名、明确跳过的内容、硬约束。本项目出现过四次偏差：

| 文档写 | 文件实测 |
|---|---|
| `frame_text.png` 1280×566 | 1280×672（顶部多了照片行），尺寸按文件保持 |
| 「RESET 三行状态齐全」 | `index.png` 第 3 行第 6 格是空的，保持空白 |
| 鼠标行在 `frame_manual` 第 1 块 | 第 1 块只有键盘行，那行在第 2 块；第 3 块是左クリック/ホイール↓ |
| `popup_parts` 只有 x 0..155、y 52..396、8 项竖排 | 4 列状态 × 9 行，文字在 x 50/266/482/698 四处；按文档做会留下四分之三英文 |

还吃过一次亏：先按早期版本把 `title.png` 写成「设置」，用户随后定稿「**环境设置**」，
只能回头重出。**文档给文案，文件给几何**；冲突按文件做，并在交付时把差异列给用户看，
不要默默改文档或默默照抄文档。明确保留/跳过的内容同样以文件为准
（`frame_voice` 不做、BGM/BGV 原样、键名原样写回、标签「キーボード」「マウス」译「键盘」「鼠标」）。

### 4.5 反复出现的调参边界

- **数据达标 ≠ 视觉达标**。`blur=6.0` 的分层数字和 `blur=5.0 / gain=2.8` 几乎一样好，
  但前者把字间 4px 空隙糊成雾板。**半径必须和字距一起看**，宁可小半径 + 高强度。
- **patch 边界要收敛在清除区内部**。patch 左界严格等于 `clear_x0`、文字起点用
  `text_x - clear_x0`，柔光往左溢出时裁切只发生在清除区内，`清除区外 0 改动` 才能过。
- **配置里加参数前先搜名字**：新参数 `INDEX_BAND` 与已有同名 tuple `(2,46)` 撞车导致
  `TypeError`，改名 `INDEX_HAZE`。
- **「看起来像裁切」先量边界再改**：4.1 第三轮实测边界实笔画裁切量为 0，
  真正原因是左沿基准写错 + 串色 + 柔光灰板。
- **原图没有的装饰一律别加**，拿不准就量剖面（3.3 红下划线）。
- **只处理文字带**：英文大字、其它 UI 语言图、字体资源文件都不在范围内。

### 4.6 用户改口时，旧结论要一起作废

第五批用户一句「你应该都居中」推翻了 `任务说明.md` 的硬约束「左对齐、勿居中」，
同一句里还把徽标从「保留不动」改成要汉化。这两条都是**上一批刚写进文档的定论**。

处理顺序：① 按用户当期口述改；② 把被推翻的结论在配置和文档里就地标注「已作废，
以第 5 批为准」，别留着让下一个接手的 AI 照抄；③ 自检判据跟着换
（`stand_parts` 从「左沿对齐」换成「六行墨迹中心 = 555」，徽标从
`keep_exact` 换成「两框有中文 + 窗口外 0 改动」）；④ 交付时明确告诉用户改了哪几条。

**别拿「文档里写了」去反驳用户，也别默默改完不回写文档。**
清单类文档（译名表、保留项）天生会随验收推进而失效，全图扫一遍英文比信清单可靠。

## 6. 第 6 批（8 张）新增坑位

### 6.1 「格内有中文」不能用固定色系判据，要用「新增字色墨迹」

同一张图里字色可能完全不同：`panel` 的 Information 是近黑 (48,46,40)，
BLOCK / PREVIEW 却是浅棕 (160,143,105) / (165,138,122)；
`config_parts` 的 MUTE 前两列是白字、后两列是深灰 (42,42,42)。
自检若统一按 `white` 或 `dark` 判，会把一半格子误报成空格
（本批 3 条假失败里占了 2 条）。

但**单纯改成「按声明的 fill 色找像素」也不行**：原图英文/纸纹常与中文同色系，
实测 `panel` 四格原图同窗的 fill 色命中就有 94 / 272 / 380 / 575 个，
光看颜色根本分不出「中文写上了」还是「英文还在」。

正解是叠加 `changed`：

```python
def new_ink(n, win, fill, tol=25):
    s, d = src(n), dst(n)
    q = d[win]; f = np.array(fill)
    fm = (np.abs(q[:, :, :3] - f).max(axis=2) <= tol) & (q[:, :, 3] > 150)
    ch = (s[win] != q).any(axis=2)
    return int((fm & ch).sum())       # 原图当成品时恒为 0
```

颜色从 `config_batch6.py` 里各格**实际声明的 `style["fill"]`** 取，
不另写一份常量，配置改了自检自动跟着改。比原来的 `white/dark` 判据更严：
既要求字色对，又要求这一处确实是新画上去的。

### 6.2 自检脚本自己也会读错图

本批「`chart_parts` 「目」已清空 残留 8 px」是纯脚本 bug：
第 [4] 节写了 `s, dd = src("config_parts"), dst("config_parts")`，
后面却拿 `dd` 去切 `chart_parts` 的擦除窗——读的是另一张图，
那块在 config 里恰好有 8 个不透明像素。**结构检查里复用中间变量最危险**，
凡是跨图取样一律显式写 `dst("某某")`。

顺带加一条「原图该窗确实有字」的检查，防止「本来就没字、擦了个寂寞」也算通过。

### 6.3 擦除窗边界差 2px，就会留一个逗号状白点

`config_parts` 右列 ALL 的旧字最右一撇落在 `x=420~421`，
而 `text_mask` 的窗右边界是 `x0+41=419`（`box_mask(pad=1)` 也只到 419），
每格都留一个白点，3 行重复。放大到 8 倍才看清。

修法不是把中文落位窗一起改宽（会移位），而是**单独把尾段白字并进擦除 mask**：

```python
tail = (x0 + 41, ry + 8, x0 + 45, ry + 19)
ts[tail] = 白字判据
stroke |= ts
erase_all |= B.dilate(ts, 3) & B.box_mask(A.shape, tail, 1)
all_cells.append(w)        # 落位窗 w 保持不变
```

配套要同步：允许改动窗口右扩 3px、右侧 `keep_exact` 禁改区起点从 420 挪到 423，
并补一条「ALL 尾笔白点已清除」防回归检查。**加一处擦除，自检的允许窗口和
禁改区都要跟着重算**，否则会报「越界」或「装饰被改」。

### 6.4 量「补丁」必须把中文笔画从均色里剔掉

`panel` 的 FLOWCHART SCALING 首版填色 `(185,187,169)` 偏暗，
目检 6 倍图是一块边界清晰的深色矩形。但用「改动区均色 vs 窗内净区均色」
量出来是 42.3，改成实测纸色 `(209,213,198)` 后还有 20.0——
**这两个数都被深色中文笔画污染了**（改动区里混着字）。

正确口径是两边都只取 `lum > 140` 的纸色像素：

```
改动区纸色 [206.4 210.3 195.4]  vs  窗内净纸色 [209.2 213.6 198.1]
=> 真实色差 2.9
```

先确认度量口径再返工，否则会为了一个不存在的补丁反复调色。
6 倍下仍可见的轻微纸纹阶梯属于 `flat_fill` 高频残差平铺，
3 倍（接近实际显示）下已不明显，不必无限打磨。

### 6.5 坏稿探针本身也要状态隔离

`_badprobe6.py` 的 `run()` 会临时把共享的 `C.DST_DIR` 指向坏稿目录。
首版没还原，探针 B 建样本时 `shutil.copy2(C.DST_DIR/...)` 实际从 `原图/` 复制，
结果 26 条全 FAIL，误以为「判据不稳」。修法是 `try/finally` 还原，
并在模块加载时先存一份 `GOOD_DST`。**验证脚本自己出错时，先怀疑脚本。**
