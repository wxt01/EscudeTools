# 交接文档

给下一个接手的人（或 AI）。目标：**十分钟内看懂这套东西是怎么想的、做到哪一步、哪些坑已经踩过。**

---

## 1. 一句话现状

一套面向 Escu:de 系 ADV 引擎的汉化工具链，已在两个真实项目上跑通全流程：
解包 → 解脚本 → 提取 → 翻译 → 质检 → 注入 → 重绘位图字库 → 回封 → 出包，
其中中文显示走「SJIS 占位字符 + 位图字库重绘」，**不改 exe、不装系统字体**。
界面文本（数据库）与部分界面图片（设置页、确认框）也做了。

---

## 2. 目标与边界

**目标**：让中文能正常显示、能通关；译文一致（人名、术语、语气）；观感尽量接近人工汉化。

**边界（发版时必须守住）**：

- 本仓库只放**工具、脚本、文档**；
- 不放游戏本体、游戏资源、脚本数据、译文、字库图、补丁成品，也不放获取途径；
- 第三方引擎工具**不随仓库分发**，只给获取与改造说明（见 `vendor/README.md`）。

代码里也不要写具体作品名。文档举例一律写"某作品"、"示例项目"。

---

## 3. 数据流

```
游戏 *.bin
   │  解包
   ▼
output/script/*.bin + *.001 ──解脚本──► script.db ──export──► 2_json_jp
output/data/*.bin ──解数据库──► db_*.db                       │
output/gfx/**                                                 │ 翻译
                                                              ▼
                                                        3_json_cn
                                                              │
        ┌─────────────────────────────────────────────────────┤
        │                                                     │
        ▼                                                     ▼
  码表 cmap.json ──► 字库页 PNG                          注入 script.db
  （中文→SJIS占位）      │                                    │
        │               ▼                                    ▼
        │         output/gfx/font/…                   script 回封 ─┐
        │                                                          │
        └────────────► 整包重打 ──► 6_release/{script,gfx,data}.bin ◄┘
```

三个包各自独立，可以只重打其中一个（`--no-gfx` 就是只重打脚本）。

## 4. 关键设计决策（以及为什么）

| 决策 | 理由 | 如果换了作品仍成立吗 |
|---|---|---|
| 走**位图字库**，不改 exe | 引擎不读系统字体（实测）；改 exe 可能触发完整性校验 | 成立，但要先确认该作品确实走位图路径 |
| 中文转**SJIS 占位字符** | 引擎按 SJIS 解码，写中文原始字节必然乱码或变 `?` | 成立 |
| 占位池排除**原文用字** | 否则残留日文会显示成别人的字形 | 成立 |
| 占位池限制**页号上限** | 引擎只渲染正文用到的页，高页画了也白画 | 成立，页号要按作品重算（`prepare.py` 自动算） |
| **译前锁定**而非译后替换 | 译后替换只能"修补"，模型可能压根没写那个词；锁定后模型看不到原词 | 成立 |
| 日文=中文的词**也锁** | 不锁就会被变体成昵称/意译，系列一致性崩 | 成立 |
| 每次构建从 **4_pristine** 复制 | 在已注入的库上再注入会累积旧占位符，越改越脏 | 成立 |
| 翻译关思考模式 | 快 3~4 倍，输出 token 降到约 1/8，质量无明显下降 | 取决于后端模型 |
| `max_lines` 熔断 | 防止一句命令误触发全量，烧钱 | 成立 |
| 索引用**指令参数**而非计数器 | 指令参数会跳号，计数器会整段错位 | 成立，任何自研脚本都要注意 |
| 未引用的消息行**也导出** | 多为选择支，漏了就残留日文 | 成立 |

## 6. 试错记录（重要：这些不要再走一遍）

| 试过 | 结果 | 结论 |
|---|---|---|
| 装系统字体 + 生成映射 TTF | 引擎不调用系统字体，字形毫无变化 | ❌ 路线作废；除非确认该作品走系统字体 |
| 改 exe 字符集（`0x80`→`0x86` + 扩字符类型表 + 改索引位移） | 单点可改，但要同时改字符类型表范围、索引换算、注音路径，漏一处就断字；且零售版可能带完整性校验 | ⚠️ 降为备选，本工具链不用 |
| 用"第几个合法 SJIS 字符"推算格子 | 与引擎公式差 1~十几格，中文画进相邻格，游戏里显示成隔壁的日文汉字 | ❌ 已改为直接套公式 |
| 只画 12~30 号字 | 32 号字号未覆盖，走该字号的文字整片空白，且极难联想到字号 | ❌ 已改为自动扫描全部字号 |
| 占位字取到 84 页以上 | 引擎不渲染那些页 → 空白。曾误判为"字库缺字" | ❌ 已加页号上限 |
| 数据库字段直接写中文 | 落盘变 `?` | ❌ 必须走占位符 |
| 纯全角拉丁条目跳过不翻 | SAVE / CONFIG 之类保持英文 | ❌ 已纳入翻译 |
| 图片文字：逐像素抠色 | 金箔/渐变底被一起抠掉 | ❌ |
| 图片文字：同色底板覆盖 | 底板与渐变背景有接缝 | ⚠️ 仅纯色底可用 |
| 图片文字：整行复制填补 | 复制到高光行会出现条纹 | ⚠️ 仅渐变底且取样行干净时可用 |
| 图片文字：按栅格切块 + 整列擦除 | 设置页三页一次成功 | ✅ 保留为主方法 |
| 图片文字：干净行复制 + 面板底色填平 | 确认框可用；标题按钮多状态行残留 | ✅ 保留（限 confirm） |
| 覆盖 80~90MB 资源包时游戏正在运行 | 磁盘 IO 打满，整机卡顿，被误认为"补丁吃内存" | ⚠️ 覆盖前必须退出游戏 |
| 码表只映射汉字、不含标点 | `——`、`·` 在 SJIS 编不了，落盘变 `?`；实测 832 行受影响，且看起来像"原文如此" | ❌ 已改为覆盖所有非编码字符，并加全量校验 |
| 锁定词表只收正式人名、不收昵称 | 同一角色出现「秋姐／明姐」「健哥／健哥哥」这类分叉；敬称 `さん` 还会把男性角色译成「小姐」 | ❌ 已把昵称、拉长音、亲昵形、敬称全部加入词表并统一存量译文 |
| 画字库用 `anchor="mm"`、字号=格边长 | 中文字体 CJK 墨迹比 em box 高，86% 的字底部被裁 1~3px；「姐」被裁成「姉」的样子，极易误判为"画错字/映射错" | ❌ 已改为量墨迹 bbox 后按墨迹居中、超高缩放；验收用「姐」的底横做样 |
| 字库按目标字号直绘（无超采样） | 小字号笔画落半像素：密横部件（青）糊死显"加重"、小部件（颤的亘部）发虚像缺笔画，会被当成多个不相关问题 | ❌ 已改 4 倍超采样（SS=4，画完缩回再墨迹居中）；验收样字：姐/请/情/颤 |
| 拿旧码表核对新包的字库页 | 整包重建会重排占位字（如「姐」:釛→釜），旧表换算出的格子在新包里是别的字，会"发现"不存在的错字 | ⚠️ 核对前先确认码表与包是同一次构建的产物 |

**一条方法论**：每次"改完看不到效果"，先做**回读校验**——从成品包里把数据解出来，
按码表反查，确认字节确实是预期内容。这能立刻区分"没写进去"和"写进去了但显示不出来"，
后者才需要动字库。

## 7. 代码地图

| 文件 | 职责 | 改动时的注意点 |
|---|---|---|
| `scripts/paths.py` | 项目目录解析 | 所有脚本依赖它，改签名要全局搜 |
| `scripts/prepare.py` | 备份/解包/解脚本/解库/提取/底版/页号 | 幂等；`--force` 会重来 |
| `scripts/hx.py` | 提取/翻译/注入/质检/槽位/替换 | 索引取值、术语锁定是核心，别退化成计数器 |
| `scripts/build.py` | 编排构建 | 顺序不能换：先字库后注入再回封 |
| `scripts/gen_font.py` | 码表 | 占位池三条排除规则 |
| `scripts/gen_fontpages.py` | 画字库页 | 必须用引擎公式；字号自动扫描；按墨迹居中防底部裁切 |
| `scripts/normalize_cn.py` | 译文清理 | 会备份；占位符清理别删多 |
| `scripts/gen_dicts.py` | 从现有译文统计词库 | 只学规律，不搬译文 |
| `scripts/make_checklist.py` | 待处理清单 | 面向非技术用户，措辞要直白 |
| `scripts/todo_gui.py` | 图形化逐条处理 | 打包成 exe 时靠 `paths.py` 找项目 |
| `scripts/replace_tool.py` | 批量替换 | 自动备份 |
| `scripts/ui_*.py` | 界面图 | 各自适用范围见 `05` |

## 8. 下一步建议（按价值排序）

1. **H 段落强度校准**：自动翻译对成人向描写偏克制。已有工具（GUI 逐条 + 批量替换），
   缺的是"按角色/场景给不同强度"的策略；可以先统计哪些行被判为成人向，再批量调整词表
2. **拟声词统一**：把 `gen_dicts.py` 产出的 `moan_pairs.tsv` 落成正式对照表，
   用 `replace` 全局统一（同一角色同一声音前后一致，比"译得准"更影响观感）
3. **标题画面按钮**：唯一干净的做法是**手工逐格标坐标 + 边缘羽化**，不是算法问题；
   28 个按钮 × 4 状态 = 112 处，属美工活
4. **语音鉴赏 / 快捷键说明页**：同 `ui_image_patch.py` 的路子，补 `ui_labels.json` 条目即可
5. **多作品适配**：把表名/列名/页号抽成 `project.json` 字段（已抽出大部分），
   补一份"新作品 checklist"就能复用

## 9. 接手后的十分钟自检

```bat
python scripts\paths.py                          :: 打印目录解析结果
python scripts\hx.py                             :: 打印用法
python -c "import json;json.load(open('config.example.json'))"
```

**第三方工具不在仓库里**。若 `project.json` 里的 `engine_tool` 为空或文件不存在，
按 `vendor/README.md` 第 0 节**自己下载编译并写回配置**，不要停在这一步等用户。

再拿一个已有项目跑一次只重打脚本：

```bat
python scripts\build.py --project <已有项目> --no-gfx
```

能出包就说明环境完好。**别看文档就当环境正常**——依赖（pillow/numpy/fonttools）、
引擎工具路径、`config.json` 都可能被搬动过。

## 11. 术语

| 词 | 含义 |
|---|---|
| 占位字符 | 中文映射到的那个 SJIS 冷门汉字；引擎按它取格子，格子里画的是中文 |
| 码表 | `cmap.json`，中文 → 占位字符 |
| 底版 / pristine | 从原版解出的、未被修改过的库与字库页，每次构建的起点 |
| 译前锁定 | 翻译前把专有名词换成占位符，译后还原 |
| 槽位 | 处理不了的长句描写留的空位，由人工填 |
| 行带 | 图片里连续若干行构成的一条文字区域 |
