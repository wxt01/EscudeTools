# 图片汉化 · 接手文档

> 目标：把**烧在 PNG 里的界面文字**（标题按钮、设置页标签、确认框、木牌、存读档大标题）换成中文。
> 产物随 `gfx.bin` 回封，与文本补丁分文件共存。
> 本页只讲「怎么接手」。完整方法论（六组案例 + 46 条错误总表）在
> [`../ui_image_toolkit/汉化方法与思路.md`](../ui_image_toolkit/汉化方法与思路.md)，出问题再读。

---

## 0. 先判型：这张图能不能做（3 分钟）

判断只有一条：**文字区域的底色能不能无损重建？**

| 底色 | 典型图 | 做法 |
|---|---|---|
| 纯色 / 竖向渐变 | 确认框勾选项、设置页标签、按钮面 | ✅ 自动化可做 |
| 透明底 + 发光字 | 右键菜单、部分按钮小字 | ✅ 精修路线可做 |
| 高光 / 水彩笔触 / 金箔纹理压在字下 | 标题画面按钮小字、存读档大标题 | ❌ 自动化必坏，保留原文 |

第三类之所以做不了：擦掉字就等于擦掉那层高光，填什么颜色都会对比出一条色带；只抠字不填色又留描边残影。**这不是调参能解决的。**

快的判型手段：量 alpha 剖面看有没有底板；多状态图做行/列两两差分看文字层是否逐像素复制。

## 1. 两条路线，怎么选

| | `scripts/ui_*.py`（自动化） | `ui_image_toolkit\`（精修） |
|---|---|---|
| 定位 | 批量替换尝试，启发式推断几何 | 逐图人工实测，几何写进 `config_batchN.py` |
| 适用 | 纯色底、简单竖向渐变 | 多状态图、透明底发光字、木牌/胶带/纸片等复杂底板 |
| 验收 | 目视 + `--preview` | 自检脚本 + 坏稿探针 + 对照图 + 成品 md5 同源 |
| 入口 | `bat\ui_automation.bat` | 按第三节流程 |

`scripts\ui_*.py` 现状（都是实测结论，不是设想）：

| 脚本 | 适用 | 结论 |
|---|---|---|
| `ui_image_patch.py` | 设置界面多页标签 | ✅ 可用（行带分离 + 整列擦除 + 原色重绘） |
| `ui_inpaint_patch.py` | 确认框、纯色底 | ✅ 可用（`confirm` 分支；`menu_button` 分支效果差） |
| `ui_cover_patch.py` | 纯色底、不在意纹理 | ⚠️ 有接缝，慎用 |
| `ui_custom_patch.py` | 文字与底色反差极大 | ❌ 金箔/渐变底会连底一起抠掉 |
| `ui_button_patch.py` | 标题按钮 4 状态 × 7 按钮 | ⚠️ 英文主标保住，日文小字擦不干净，不建议启用 |

`build.py` 会自动调用自动化路线：给了 `ui_labels.json`（设置页）或 `ui_misc.json`（零散图）才跑。

## 2. 自动化路线怎么用

1. 复制 `ui_labels.example.json` 为**游戏文件夹**下的 `ui_labels.json`，按实际图改 `rows` / `texts`。
2. 复制 `ui_misc.example.json` 为 `ui_misc.json`，`type` 取 `confirm` / `title` / `menu_button`。
3. 单独调试（不要直接往包里塞）：

```bat
python scripts\ui_image_patch.py --in <4_底版\gfx\sys> --out out --labels ..\ui_labels.json --preview p.png
python scripts\ui_inpaint_patch.py --in <4_底版\gfx\sys> --out out --config ..\ui_misc.json --only common/confirm_parts.png
```

**永远从原版图（`4_底版\gfx\sys`）出发**。擦除是破坏性的，在改过的图上再改一次会越来越脏。

## 3. 精修路线怎么走（ui_image_toolkit）

### 工作区（跟游戏走）

所有 `config_*.py` 通过 `_work.py` 解析工作区，顺序：
`UI_WORK_ROOT` 环境变量 → 当前项目（向上找 `project.json`）的 `7_图片\` → 旧布局 `12_界面图工作区\` → 工具包内 `_工作区\`。

```
<游戏>\7_图片\
├── 待做原图\   主对话放进来的日文原版图
├── 待交付\     成品 + 对照图，等验收
├── 工作输出\   npy 掩码、诊断图、临时对照
├── 交付归档\   历史任务说明与旧成品
├── 探索脚本\   一次性探针
└── 回归基准\   调试用差异样本
```

### 标准接手流程

1. 原图进 `待做原图\`，同时拿到译文定稿。
2. **增量修改一律以最新已汉化版为底图**，不是游戏原版。
3. 侦察：尺寸/通道 → alpha 分层 → 逐格底板与字色 → 多状态差分 → 圈出禁改装饰。
4. 新建 `config_batchN.py`，坐标颜色字号**全部从文件实测**，不抄文档估算值。
5. `build → verify → _badprobe → compare` 全绿，再放大与 1:1 各看一遍。
6. 成品与对照图放 `待交付\`，验收后改名归位到 `gfx\sys\<子目录>\`。

### 四件套

| 文件 | 作用 |
|---|---|
| `config_batchN.py` | 几何、译名、字色、样式（改配置优先改这里） |
| `build_batchN.py` | 生成成品 |
| `verify_batchN.py` | 自检：窗口外 0 改动 / 旧字墨迹已擦 / 逐格有中文 / 装饰逐像素保留 |
| `compare_batchN.py` | 分组对照图 + 成品 md5 前后同源 |
| `_badprobeN.py` | 坏稿探针：故意抹回英文，确认自检拦得住 |

通用底座：`repair.py`（三种补底）、`texture.py`（已弃用的整行平移，反面参考）。
第一批示例在 `examples\menu_button_单图\`（含 `layout.py` 的对齐量法、`inspect_sprite.py` 的结构诊断），**几何参数勿照抄**。

## 4. 验收清单

- [ ] 原日文**一点不剩**（含笔画边缘、标点）
- [ ] 没有色带、色块接缝、重影
- [ ] 字号 ≈ 原字高（用像素量，别按面板高度估）
- [ ] 描边克制（1px、半透明），远看不像「贴上去的」
- [ ] 装饰元素（笔触、勾选框、照片）逐像素完好
- [ ] 多状态行全部换字，状态间只有该变的变
- [ ] 文字在行/块里视觉居中（或按原图左对齐）
- [ ] 尺寸、部件格一像素未动

---

## 5. 做不了的怎么办

保留原文，并在补丁的 `使用说明.txt` 里写明。行业常见做法是「标题按钮留英文」——玩家看到一句英文不会觉得是 bug，看到一块被抹花的水彩会。

---

## 6. 红线

- **`gfx\font\`（位图字库页）一个像素都不能动**——那是文本汉化的字库，两套管线共用 `gfx.bin`。
- 交付归档、工作输出、探索脚本、回归基准里的图都含游戏美术，**永不入库、永不外传**。
- 明确保留项（数字、图标、LOGO、音声人名）一字不碰。
- 环境里跑不了游戏，三态切换的实际观感仍需真人在游戏内验收。
