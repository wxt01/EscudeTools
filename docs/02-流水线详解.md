# 流水线详解

每个脚本：干什么、参数、输入输出、失败怎么查。

## 目录约定

```
<项目>/
├── project.json
├── 0_backup/      原版资源包备份
├── 1_unpack/      解包产物；output/ 下是 script/ data/ gfx/
├── 2_json_jp/     日文 JSON
├── 3_json_cn/     译文 JSONL
├── 4_pristine/    干净底版（每次构建的起点）
├── 5_build/       中间产物（cmap、字库页、界面图）
└── 6_release/     成品
```

`paths.py` 负责解析：`--project` 参数 → `HANHUA_PROJECT` 环境变量 → 向上找 `project.json` → 当前目录。

## prepare.py —— 准备

```bat
python prepare.py --project <目录> [--game <游戏目录>] [--tool <引擎工具>] [--force]
```

七步：备份 → 解包 → 解脚本 → 解数据库 → 提取 → 干净底版 → 推断页号。

- `--force`：已存在的产物重新生成（解包、提取都会重来）
- 幂等：不加 `--force` 时，已有产物会跳过，可以安全重复运行
- 推断页号：扫描 `2_json_jp` 里所有双字节 SJIS 字符，算出实际用到的最大页号，写入
  `project.json` 的 `font.max_page`。**这一步别跳过**，它决定占位字能落在哪些页（见 `03`）

## hx.py —— 提取 / 翻译 / 注入 / 质检

| 命令 | 用法 | 说明 |
|---|---|---|
| `stats` | `hx.py stats <script.db>` | 脚本数、行数、字数 |
| `export` | `hx.py export <script.db> <输出目录>` | 每脚本一个 JSON，按 `INST_TEXT` 参数取行号 |
| `translate` | `hx.py translate <json目录> <输出目录>` | 批量翻译，断点续跑 |
| `check` | `hx.py check <json目录>` | 质检 |
| `inject` | `hx.py inject <script.db> <json目录> [cmap.json]` | 写回数据库；给码表则转占位符 |
| `slots` | `hx.py slots <json目录> <out.tsv>` | 导出可编辑表格 |
| `fill` | `hx.py fill <json目录> <in.tsv>` | 按表格回填 |
| `replace` | `hx.py replace <json目录> <map.tsv>` | 全文批量替换（查找<TAB>替换） |

### export 的两个关键设计

1. **索引取 `INST_TEXT` 的参数值**，不是计数器（原因见 `03` 第二节）
2. **未被引用的消息行也导出**，标 `note: "未引用"`，这些多是选择支文案；
   同时生成 `_未引用台词.txt` 供核对

### translate 的提示词结构

每条发给模型的内容包含：

- 角色 ID（`char` 字段）对应的中文名与语气说明（来自 `characters.tsv`）
- 前 N 行原文（`context_lines`）作为上文
- 术语表里出现的词（同时做**译前锁定**，替换成 `〖Tn〗` 占位符）
- 控制标记占位化（`<r>`、`<ruby>` 换成 `【n】`），避免模型改动

返回后依次：还原术语 → 还原标记 → 写入 JSONL。

**解析失败会二分重试**（20 条失败就拆 10+10），最小到单条；单条仍失败则记空译，进质检。

### 译前锁定为什么必须做

只把词表塞进提示词，模型仍然可以自由发挥：`シンジュ` 可能被写成"神珠"、"心之珠"。
锁定之后模型**看不到原词**，只能原样保留占位符，译后强制还原，一致性接近 100%。

注意：**日文与中文写法相同的词也要锁**（例如人名本身就是汉字），否则会被变体成昵称或意译。

### check 的四类问题

| 类型 | 判定 |
|---|---|
| 空译 | `zh` 为空 |
| 残留假名 | 译文里还有平假名/片假名（排除刻意保留的） |
| 长度溢出 | 中文长度超过原文 1.3 倍且绝对值较大（对话框会溢出的信号） |
| 标记丢失 | 原文有 `<r>` 而译文没有 |

## normalize_cn.py —— 译文清理

```bat
python normalize_cn.py --project <目录> [--dry]
```

三件事：

1. 去掉 `<ruby text='かな'>汉字</ruby>` 的注音，只留汉字（中文不需要假名小字）
2. 把残留的日文假名拟声规范成中文写法（`ぁ`→啊、`ん`→嗯、`ッ`/`ー`→去掉，压缩过长拖音）
3. 清掉没被还原的占位符（`〖T0〗`、`【3】`）

第 3 条很重要：这类字符不在 Shift-JIS 范围内，写进脚本会变成 `?`，
在游戏里表现为句子里突然冒出 `?T0?` 之类的东西。

**自动备份**到 `备份/<时间戳>/`。

## gen_font.py —— 码表

```bat
python gen_font.py --text <译文目录> --out <输出> --exclude-text <日文目录> --max-page 83 [--base 字体]
```

产出 `cmap.json`：`{"中": "占位字符", ...}`。

占位池 = JIS 汉字 − 日文原文用字 − 译文用字 − 常用字，且只取 `page <= max-page`。
另外输出 `report.txt`：占位字符数、落在哪些页、有没有覆盖不到的字。

## gen_fontpages.py —— 画字库

```bat
python gen_fontpages.py --cmap cmap.json --fontdir <原字库 ja_jp> --out <输出> [--font 字体] [--index 0]
```

- 复制原字库目录（保住所有其他页），按码表把中文字形画进对应格子
- 字号目录**自动扫描**，不必手写列表（漏字号会导致整片空白）
- 只改有占位字的格子，其余像素原样保留

## build.py —— 构建

```bat
python build.py --project <目录> [--no-gfx] [--skip-ui]
```

顺序：收集用字 → 码表 → 字库页 → 界面图 → 注入脚本 → 写人名/界面 → 回封数据库 → 整包 → 输出。

- 每次都从 `4_pristine` 复制干净底版再写。**不能在已注入过的库上再注入一次**，
  否则旧占位符会被当正常字符留下，越改越脏
- `--no-gfx`：跳过码表与字库（改译文时用）
- `--skip-ui`：跳过界面图

## 引擎工具的四个命令（易错点）

| 命令 | 正确用法 | 常见错误 |
|---|---|---|
| `-u <目录>` | 目录里放 `.bin`，输出到 `output/` | 把单个文件当参数传 |
| `-v <script目录> -t 0` | 生成同级 `script.db` | 传 `output` 而不是 `output/script` |
| `-e <script.db> -t 0` | 产物在 `<db目录>/repack/` | 传目录或 `.bin` → 直接报错 |
| `-f <目录>` | 目录里**只能放 `db_*.db`** | 把 `script.db` 也放进去 → 表名解析异常 |
| `-r <output目录>` | 重新打出所有 `.bin` | `output/repack` 没清理就打包 |

`-e` 跑完末尾常抛一个异常（程序在等按键），**属正常**，只要 `repack/` 里有产物就行。

回封后体积变大是正常的（不重新压缩），引擎能读。

## 面向使用者的三个工具

| 脚本 | 入口 | 行为 |
|---|---|---|
| `todo_gui.py` | `tools\汉化待办.exe` 或 `bat\todo_gui.bat` | 分类待办、逐条改、保存即写回、自动备份 |
| `replace_tool.py` | `bat\replace_tool.bat` | 输入词 → 看命中 → 输入新词 → 批量替换 |
| `make_checklist.py` | `bat\make_checklist.bat` | 生成 `待处理清单.txt` |

三者都接受项目目录作为第一个参数（拖文件夹到 bat 上即可），只读写 `3_json_cn`，
**不碰游戏文件**。改完要跑 `build.py --no-gfx` 才进游戏。

`todo_gui.py` 的分类规则：

| 类别 | 判定 |
|---|---|
| 未译 | `zh` 为空 |
| 成人向 | 文件名含 `_H`，或原文命中敏感词表 |
| 拟声词 | 原文含喘息特征且很短 |
| 超长 | 中文长度超过阈值 |
| 残留日文 | 译文里还有假名 |
