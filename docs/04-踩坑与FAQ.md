# 踩坑与 FAQ

按「现象 → 原因 → 处理」组织。多数坑在别的作品上会重复出现，遇到怪现象先在这里找一遍。

---

## 一、显示层：字没了、字错了

### 1. 整片字空白（不是方块，也不是乱码）

**原因**：占位字落在了引擎不渲染的页。

引擎只渲染正文实际用到的那批页。实测某作品正文只用到第 1~83 页，
84 页以上文件存在、格子也画了字，但**引擎根本不读**，显示成空白。
表现很有迷惑性：不是全屏空白，而是"某些常用字偶尔空一个"——因为只有那部分字被分配到了高页。

**处理**：`prepare.py` 已经会算最大页号并写进 `project.json`；确认 `font.max_page` 是实测值，
重跑 `build.py` 即可。

### 2. 只有部分界面/名字栏空白

**原因**：字号没画全。原版有 11 个字号（12~32），漏掉任何一个，走那个字号的文字就整片空白。

**处理**：`gen_fontpages.py` 已改为自动扫描字号目录；确认 `4_pristine/gfx/font/<lang>/` 下所有数字目录都被覆盖。

### 3. 显示出来是"别的日文汉字"，看着像没翻

**原因**：格子算错位了。用"第几个合法 SJIS 字符"推算格子，与引擎公式差一格到十几格，
中文被画进相邻格子，引擎取到的是隔壁的日文汉字。

**处理**：严格用 `03-引擎技术笔记.md` 第四节公式。验证法：取一个已知汉字（如"亜"），
按公式算出页/格，打开那张 PNG 看那一格是不是它。

### 4. 满屏问号，或句子里冒出 `?T0?`

**原因**：写了 Shift-JIS 编码不了的字符。两种来源：

- 直接写中文（数据库字段、脚本字符串都一样）
- 占位符没被还原（模型把 `〖T0〗` 弄丢了），它超出编码范围，落盘时变成 `?`

**处理**：正文与数据库都必须走占位符；`normalize_cn.py` 会清掉残留占位符，
`hx.py check` 会报异常字符。

### 5. 对话框里字挤在一起 / 断字

**原因**：只换字体、没换字符集，双字节被当成两个半角字符处理。

**处理**：本工具链不写中文原始字节，写的是**合法的 SJIS 占位字符**，从根上绕开这个问题。
如果走了"改编码"路线，必须同时处理：字符类型表范围、`sjis_to_jis()` 的位移量（GBK 与 SJIS 不同）、
注音路径，漏一处就断字。

### 6. 标点变成问号（`——` 显示成 `??`）

**原因**：码表只把「汉字」纳入了映射，标点没纳入。而中文常用的 `—`（U+2014）、`·`（U+00B7）
在 Shift-JIS 里编码不了，落盘时被替换成 `?`。
实测某项目里 `——` 出现 2,012 次、`·` 122 次，整整 832 行受影响——而且**看起来像是"原文就这样"**，
很容易被当成正常现象放过。

**处理**：码表要覆盖**所有"编码不了"的字符**，不限于汉字：

```python
cjk |= {c for c in need if ord(c) > 0x7F and not encodable(c)}
```

改完必须全量重建（加映射要重画字形）。验收方法：把成品包的脚本解出来，
逐字检查 `ch in cmap or ch.encode("cp932")` 是否成立，应为 100%。

### 7. 个别符号显示成方块或空白

**原因**：该符号在渲染用的字体里没有字形（例如音符 `♪` 在某些中文字体里缺失）。

**处理**：要么给这个码位单独画字形，要么在译文里换成等效写法。

### 8. 字显示成"缺了底横的另一个字"，且所有字的底边都被削一截

**现象**：最典型的例子——「姐」显示成「姉」的样子。不是画错了字，
是**且字的底横出了格子边界被裁掉**，剩下的部分恰好长得像另一个字。
放大看会发现所有中文的底部都缺 1~3px，只是大部分字被裁了也不容易认错，
「姐」这种恰好变成另一个常用字的才会暴露。

**原因**：画字库时用 `anchor="mm"` 把 字号=格子边长 的字形直接居中画进格子。
中文字体的 CJK 墨迹本来就比 em box 高，底部必然溢出格子；
实测 2509 字里有 2170 字（86%）底部超出，最深的超出 3px。

**处理**：`gen_fontpages.py` 已改为「**4 倍超采样**（按 4 倍字号绘制再缩回）→
量墨迹 bbox → 按墨迹居中贴入格子 → 个别超高的字等比缩到格内」。
超采样是必须的：小字号直绘时笔画落在半像素上，密集部件（如"青"的横画）
糊死显重、稀疏小部件（如"颤"的亘部）发虚缺笔画，用户会分别报告为
"某些字加重"和"某些字缺一块"，其实是同一个问题。
若以后换字体或调整绘制逻辑，务必用「姐／且／量」（看底横）、
「请／情」（看青部是否糊）、「颤」（看亘部是否完整）做验收样字。

**核对字库时的一个陷阱**：整包重建会**重新分配占位字**（译文用字集合一变，
分配就变，例如「姐」上一版映射「釛」、下一版可能映射「釜」）。
script/gfx/data 三包是按同一份码表同时生成的，永远自洽；
但拿**旧码表**去核对**新包**的字库页，就会"发现"错字——其实没问题。
查包前先确认码表 mtime 与包是否同一次构建产物。

## 二、数据层：改了没效果

### 6. 人名还是日文

**原因**：人名不在剧本包里，在 `data.bin` 的数据库里；只改 `script.bin` 不会变。

**处理**：填 `names_zh.json`（`{rowid: 中文名}`），`build.py` 会写入并回封 `data.bin`。
注意必须走占位符，否则变 `?`。

### 7. 菜单里 SAVE / CONFIG 之类还是英文

**原因**：这些是**文字**（`TEXT_00` 里的 `LT_ADV_*`），不是图片。
导出时若按"含日文才算待译"过滤，纯全角拉丁的条目会被漏掉。

**处理**：把这类条目补进 `ui_zh.json`。

### 8. 设置界面 / 标题按钮还是日文

**原因**：那是**图片**，文字烧在 PNG 里，改数据库无效。

**处理**：见 `05-界面图汉化.md`。注意其中一部分（文字背面压着高光/笔触的）自动化做不干净，
硬做会破坏原画质感，不如保留。

### 9. 译文贴错行（张冠李戴）

**原因**：用"第几条 TEXT 指令"当索引，而实际指令参数会跳号，跳号之后整段错位。

**处理**：索引必须用 `INST_TEXT` 的参数值。`hx.py export` 已按此实现；
自写脚本时务必核对 `INST_TEXT` 参数序列是否连续。

### 10. 选择支还是日文

**原因**：选择支文本不被 `TEXT` 指令引用，按"只导出被引用的行"就会漏。

**处理**：`hx.py export` 会把未引用行一并导出（`note: "未引用"`），并生成 `_未引用台词.txt`。

## 三、流程层：工具报错

| 现象 | 原因 | 处理 |
|---|---|---|
| `-e` 报 Invalid Path / SQLite 异常 | 输入传了目录或 `.bin` | 必须传 `script.db` 文件 |
| `-f` 报 FormatException | 目录里混进了 `script.db` | 只放 `db_*.db` |
| `-r` 打出来的包缺文件 | `output/repack` 残留 | 打包前删掉 `repack` |
| 回封后包变大很多 | 不重新压缩 | 正常，引擎能读 |
| 解包后没有 `output/script` | 包不是 `ESC-ARC2`，或 `bins` 配错 | 看头部 8 字节 |
| 二次注入后译文变乱 | 在已注入的库上又注了一遍 | 每次都从 `4_pristine` 复制 |

## 四、运行时：卡顿、闪退

### 11. 覆盖资源包时整机卡住

**原因**：游戏正在读那个文件（`gfx.bin` 常有 80~90MB），同时系统在扫新文件，
磁盘 IO 被打满。不是内存泄漏，也不是补丁有问题。

**处理**：**覆盖前先退出游戏**。这一条写进补丁的使用说明里。

### 12. 换 exe 之后启动不了

**原因**：零售版可能带完整性校验。改 exe 字节（例如改字符集判断）会触发失败。

**处理**：本工具链不改 exe，天然规避。若必须改，先确认该版本有没有校验，
并且**测试基线一律用零售原版 exe**——用第三方改过的 exe 测出来的结果不代表玩家环境。

### 13. 补丁放进去没反应，还是日文

按顺序排查：

1. 覆盖的是不是**游戏实际启动的那个目录**（有多个副本时最容易搞错）
2. 文件确实是新的（比对大小/哈希，回封后的包体积会明显不同）
3. 游戏是否在读别的包（有的版本会优先读外部目录）
4. 脚本回封是否真的产出了文件（看 `output/repack/` 是否有内容）

## 五、翻译质量类

| 现象 | 原因 | 处理 |
|---|---|---|
| 同一角色称呼忽变 | 没做译前锁定，或锁定词表里没这个词 | 补 `glossary.tsv`；汉字同形的词也要写 |
| 人名被意译 | 同上 | 同上 |
| 句子太书面、翻译腔 | 提示词缺示例 | 用 `gen_dicts.py` 产出 `style_ref.md` 当 few-shot |
| 短句被"补全"成长句 | 模型倾向补全主语 | 提示词强调"保持短句、不要补主语"；或提高 `batch_size` 让上下文更完整 |
| 拟声词前后不一致 | 没有统一对照表 | 建拟声词表，用 `replace` 全局统一 |
| 出现 `？？` | 多为原文如此（角色发懵） | 先统计原文是否也有，别急着改 |

### 称呼不一致（同一个人出现两种叫法）

**现象**：同一个角色，有时叫「秋姐」有时叫「明姐」；有时叫「健哥」有时叫「健哥哥」。
日文原文其实是同一个词（例如 `あき姉`），译文却分叉了。

**原因**：锁定词表里只有**正式人名**（`秋葉`），没有**昵称与敬称**（`あき姉`、`けん兄`、`つぐ姉`）。
昵称不在锁定范围内，模型每次自由发挥：`あき` 可以读成「秋」也可以读成「明」。

**处理**（三步，缺一不可）：

1. **补词表**：把所有昵称/敬称形式写进 `glossary.tsv`，包括拉长音的变体
   （`あき姉ぇ`）、亲昵形（`つぐちゃん`）、敬体（`けん兄さん`、`秋葉さん`）。
   匹配按长度优先，长的写前面不会冲突。
2. **批量替换已有译文**：先换长串再换短串（否则 `小秋姐` 会被 `秋姐` 规则拆坏），
   注意别误伤普通名词（例如角色名单字与常用词同形时）。
3. **重新构建**，并抽查：统计每个变体的出现次数，异常项应为 0。

**验收口径**：同一日文形式，全库只对应一种中文写法。可以用一个小脚本按
「日文 token → 中文变体计数」统计，出现两个以上变体就是漏了。

**一个易混点**：敬称 `さん` 要按说话人身份定。同一角色被不同人称呼时，
`秋葉さん` 应统一为一种译法（如「秋叶先生」），不要一半「小姐」一半「同学」——
尤其别把男性角色译成「小姐」，那是模型没认出性别。

## 六、验证习惯（省时间）

1. **先验证显示层，再全量翻译。** 只翻十几行就能确认"中文能不能画出来"，
   这一步不过，翻 3 万行也没用。
2. **每次构建前后比对哈希。** 确认产物真的更新了，避免"改了没生效"的假象。
3. **回读校验。** 从成品包里把脚本解出来，按码表反查，看是不是预期的中文——
   这比进游戏逐句看快得多。
4. **抽样看点。** 字库改动后，取一页 PNG 直接看，比进游戏找那句话快。
