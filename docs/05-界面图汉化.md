# 界面图汉化

界面里的文字分两类：

- **文字层**（数据库里的 `TEXT_00`）→ 改 `ui_zh.json` 就行，见 `02-流水线详解.md`
- **图片层**（直接画在 PNG 里的）→ 本文

先判断属于哪类：把 `gfx/sys/**` 的图打开看一眼，有字就是图片层。

---

## 一、先判型：这张图能不能做

不是所有图片文字都能自动替换。判据只有一条：

> **文字区域的底色，能不能无损重建？**

| 底色情况 | 例子 | 可做性 |
|---|---|---|
| 纯色 | 确认框勾选项的白字压在深色矩形上 | ✅ 容易 |
| 竖向渐变 | 设置页标签、按钮面 | ✅ 可以（按列插值/复制干净行） |
| 文字背面有高光、水彩笔触、金箔纹理 | 标题画面按钮小字、存读档大标题 | ❌ 自动化做不干净 |

第三类之所以做不了，是因为**擦掉字就等于擦掉那层高光**，无论用什么颜色填回去都会对比出一条色带；
而"只抠字不填色"又会留下描边残影，看起来像重影。这不是调参能解决的。

---

## 二、四套实现与实测结论

脚本都在 `scripts/`，共用一个思路：定位文字 → 抹掉 → 用原字色重绘。

| 脚本 | 思路 | 适用 | 实测结论 |
|---|---|---|---|
| `ui_image_patch.py` | 按行分离「文字带」与下方笔触（笔触行像素数会突然翻倍）→ 行内按栅格切块 → **整列擦除** → 采样原文字色重绘 | 设置界面多页标签 | ✅ 可用，三页共 26 个标签一次成功 |
| `ui_inpaint_patch.py` | 找出文字行 → **复制邻近的干净行**覆盖 → 重绘；`confirm` 分支用面板底色填平 | 确认框勾选项、纯色底 | ✅ 可用（确认框）；标题按钮效果差 |
| `ui_cover_patch.py` | 直接盖一块同色底板再写字 | 纯色底、不在意纹理 | ⚠️ 有接缝，慎用 |
| `ui_custom_patch.py` | 逐像素抠掉暗色/亮色文字 | 文字与底色反差极大时 | ❌ 金箔/渐变底会把底一起抠掉 |

`ui_button_patch.py` 是专门啃「4 状态 × 7 按钮」标题图的实验脚本，结论：
**英文主标能保住，日文小字擦不干净**（那行字下面压着一层高光），不建议启用。

### 为什么 `ui_image_patch.py` 能成

1. **行带分离**：水彩笔触那几行的不透明像素数会突然翻好几倍，用这个当分界线，比按固定坐标切稳
2. **整列擦除**：只擦文字所在列的一段，笔触在别的列，天然保住
3. **采样原色**：从原文字像素里取中位色，白字还是白字、青字还是青字，不会突兀
4. **细描边**：1px、半透明，只用来保证深色底上可读，不做粗黑边（粗黑边会显得"贴上去的"）

## 三、怎么用

### 1. 设置界面（多页标签）

复制 `ui_labels.example.json` 为 `<项目>/ui_labels.json`，按实际图改：

```json
{
  "font": "C:\\Windows\\Fonts\\msyh.ttc",
  "pages": {
    "config/frame_text.png": {
      "rows": [3, 3, 3],
      "texts": ["第一行左", "第一行中", "第一行右", "第二行左", "..."]
    }
  }
}
```

- `rows` 是**每一行有几个标签**，必须和图一致；数量对不上脚本会打印「检测 N 块，文案 M 条，跳过」
- `texts` 顺序 = 从上到下、从左到右
- 键是相对 `gfx/sys/` 的路径

`build.py` 会自动调用（给了 `ui_labels.json` 才跑）。

### 2. 零散图（确认框、存读档标题）

复制 `ui_misc.example.json` 为 `<项目>/ui_misc.json`：

```json
{
  "jobs": [
    { "file": "common/confirm_parts.png", "type": "confirm", "text": "下次不再确认" },
    { "file": "file/save_title.png", "type": "title", "text": "存 档" }
  ]
}
```

`type` 三种：

| type | 行为 |
|---|---|
| `confirm` | 找底部面板里的三块勾选项，填平后写同一句文案 |
| `title` | 找中央暗色大字区域，整块重建后写标题 |
| `menu_button` | 按 4 行 × N 列切按钮，只换英文下方的小字（**通常做不干净**） |

### 3. 单独调试

```bat
python scripts\ui_image_patch.py --in <原版 gfx\sys> --out out --labels ..\ui_labels.json --preview p.png
python scripts\ui_inpaint_patch.py --in <原版 gfx\sys> --out out --config ..\ui_misc.json --only common/confirm_parts.png
```

`--preview` 会把结果合成到深色底上输出一张图，先看图再构建，别直接往包里塞。

**始终从原版图（`4_pristine/gfx/sys`）出发**，不要在已经改过的图上再改一次——擦除是破坏性的，叠加会越来越脏。

## 四、验收清单

改完必须逐条看：

- [ ] 原日文**一点不剩**（尤其笔画边缘、标点）
- [ ] 没有色带、色块接缝、重影
- [ ] 字号 ≈ 原字高（用像素量，不要按面板高度估算——实测差 1.5 倍很常见）
- [ ] 描边克制（1px、半透明），远看不像"贴上去的"
- [ ] 装饰元素（笔触、勾选框、照片）完好
- [ ] 文字在整个行/块里视觉居中，不在偏左

---

## 五、经验值

- 字高优先：`font_size ≈ 实测字高 × 0.95`。按容器高度百分比算，误差很大
- 颜色优先：从原字像素采样中位色，比固定白色自然
- 文字宽度：中文比日文短，2~4 字常见；字号别为了"填满"而放大
- 一次只改一张图、看一张预览。批量跑完再看，出问题时不知道是哪张

---

## 六、做不了的怎么办

保留原文，并在补丁的使用说明里写明。这是行业常见做法：很多汉化补丁的标题画面按钮仍是英文。

比"做坏了"好。用户看到一句英文按钮不会觉得是 bug，看到一块被抹花的水彩会。
