# 文本汉化 · 接手文档

> 目标：把一个 Escu:de 作品的**对话与界面文本**变成中文，并产出可覆盖的 `script.bin` / `data.bin`。
> 图片里的文字不走这条线，见 [`02-图片汉化-接手.md`](02-图片汉化-接手.md)。
> 目录与命令见根目录 `README.md`。

---

## 0. 先确认三件事（缺一件就别开工）

| 检查 | 怎么查 |
|---|---|
| 解包器在位 | `工具\engine\EscudeTools.exe` 存在，且能 `-u` 解包 |
| 游戏文件夹有 `project.json` | `python 工具\scripts\paths.py`（在游戏文件夹里跑），八行全 ✓ |
| 原版已备份 | `0_原版\` 里有 `script.bin` / `data.bin` / `gfx.bin` |

`paths.py` 输出里有任何一行是 `·`（不是 ✓），说明该段目录没建或配置指错，先修配置。

---

## 1. 全流程与每一步的产物

| 步 | 命令 | 产物 |
|---|---|---|
| ① 备份+解包+解脚本+提取 | `python scripts\prepare.py --project <游戏>` | `0_原版\`、`1_解包\output\`、`2_日文文本\`、`4_底版\` |
| ② 翻译 | `python scripts\hx.py translate <游戏>\2_日文文本 <游戏>\3_译文` | `3_译文\*.jsonl` |
| ③ 清理 | `python scripts\normalize_cn.py --project <游戏>` | 就地改 `3_译文\`，并写一份快照到 `3_译文\备份\` |
| ④ 质检（快，只看统计） | `python scripts\hx.py check <游戏>\3_译文` | 统计与行号 |
| ⑤ **出厂质检（闸门）** | `python scripts\qa_text.py --project <游戏>` | `审校报告.txt`；退出码 2 = 不许出包 |
| ⑥ 构建 | `python scripts\build.py --project <游戏>` | `6_补丁\script.bin / gfx.bin / data.bin` |

`prepare.py` 是幂等的；加 `--force` 才会重来一遍。

**⑤ 已经内置进 ⑥**：`build.py` 在注入前自动跑一次 `qa_text.py`，拦截项不为 0 就中止，
除非显式加 `--skip-qa`（不推荐）或 `--strict-qa`（警告也算失败）。

### 出厂质检查什么（`qa_text.py`）

| 级别 | 项目 |
|---|---|
| 拦截（必须清零） | 空译、译文是乱码、残留假名/半角片假名、残留占位符、残留 ruby、首尾空白、与原文相同、繁体/日文写法、**人名错位**、**英文夹在句中**、**用字无占位（会变问号）**、占位冲突、占位越界、字库无墨迹、项目自定义名词异体 |
| 警告（人工判断） | 疑似日文语尾、过短/过长、引号括号不配对、数字丢失、非拟声复读、术语命中率 <85%、专名缺失、角色自称混用、你/您混用、同一原文多种译法、感叹问号强度下降、长段无标点、英文单词残留、句末标点缺失 |

> 几条「不亲自玩也能查出来」的经验：
> · **人名错位**（原文是 A，译文写成 B）靠 `词典\names_map.tsv` 查，格式 `日文名<TAB>中文名`；
>   只有「译文冒出的那个名字原文里根本没出现」才算错位，同一句里本来就有多人不算。
>   ruby 读音（`<ruby text='エル'>死体</ruby>`）要先剥掉再比对，否则满屏误报。
> · **英文夹在句中**（`秘裂already溢满爱液`）几乎一定是模型漏译，直接拦。
>   `RGB/alpha/skew` 这类技术词和 `ON/OFF/CONFIG` 属白名单。
> · **用字无占位**：改了译文却没重跑全量构建，新字没进码表 → 注入时变 `?`。
>   这条专治「改完忘了 rebuild」。
> · **自称混用**只统计对白行（`“…”` 开头）；旁白也会带角色 id，混在一起必然误报。
> · **抽检表**：`qa_text.py --sample 80` 会导出 `人工抽检表.tsv`，
>   风险高的行排在前面、后接随机抽样，人工过目 80 行就能覆盖主要写法。

想加项目专属检查：在 `3_译文\词典\names_variants.tsv` 里写 `标准写法<TAB>异体写法`，
命中即拦截（例如 `持铭者<TAB>铭持`）。

### 原文自身是乱码时（`fix_mojibake.py`）

个别作品有少量台词，**官方数据本身就是乱码**（UTF-8 被按 SJIS 读出的残渣，原版游戏同样显示乱码）。
字节不可逆，但可以按「可还原片段 + 上下文」重写成中文：

```bat
python scripts\fix_mojibake.py export 3_译文 乱码待改.tsv   :: 列出：坏原文/还原片段/现译/上下文
:: 填最后一列「改写」
python scripts\fix_mojibake.py fill 3_译文 乱码待改.tsv     :: 回填并标 src_note=mojibake_rewritten
python scripts\build.py --project . --no-gfx
```

重写过的行会被 `qa_text.py` 认出来，不再重复报「译文是乱码」。

## 2. 翻译这一步的规矩

- **译前锁定术语**：`hx.py` 先把 `3_译文\词典\glossary.tsv` 里的专有名词替换成占位符再送模型，译后还原。模型全程看不到原词，所以不会自己造译名。
- **日文=中文的词也锁**（汉字人名、地名）。不锁就会被变体成昵称。
- **`<r>` 换行标记必须原样保留**，数量也要一致。
- **引号口径按用户定稿**：本作要求保留日式 `「」『』`（对白 `「」`、术语 `『』`），
  与原文括号序列逐位对齐；`config.json` 里 `quote_style=jp`。
  若某作要求中文引号，改 `quote_style=cn`，并在译后用 `replace` 统一回改。
- **`max_lines` 是熔断**：单次运行的行数上限，防止一条命令误触发全量、烧钱。
- 术语表格式：`日文<TAB>中文<TAB>说明(可选)`；角色语气表：`角色ID<TAB>中文名<TAB>语气说明`。

词典放 `3_译文\词典\`，由 `config.json` 的 `asset_dir` 指定。**不要**把 A 游戏的词表放进 `scripts\`——一套工具服务多个游戏时会串词。

## 3. 构建这一步的规矩

- **每次都从 `4_底版\` 复制干净底版**再注入。在已注入的库上反复写，旧占位符会被当成正常字符留下来，越改越脏。
- **`--no-gfx`** 只跳过「重画字库 + 替换界面图」，但仍会整包重打 `gfx.bin`。所以它要求 `1_解包\output\gfx\font\ja_jp\` 里已经是汉化字库页；脚本会抽样比对底版，**没画过就拦下来**，避免把中文打成原版。
- **用字校验**：译文里出现码表没有、且 SJIS 编不了的字，游戏里会显示 `?`。改译文后用全量构建重算码表即可覆盖；`全量 → --no-gfx` 的顺序不能颠倒。
- 三包永远同一次构建产出（`script` / `gfx` / `data` 的占位字必须自洽）。

## 4. 验收（构建完必做）

- [ ] `hx.py check` 五项全 0：残留假名 / 空译 / 标记丢失 / 过长 / 总数对得上
- [ ] 进游戏跑一遍：序章、选项分支、存档界面、设置界面
- [ ] 抽查人名与称谓一致性（术语表命中的词只应有唯一译法）
- [ ] `6_补丁\使用说明.txt` 已写明未处理项（图片文字、视频字幕、语音）

## 5. 三个给非技术使用者的工具

| 工具 | 入口 | 用途 |
|---|---|---|
| 汉化待办 | `tools\汉化待办.exe`（或 `bat\todo_gui.bat`） | 逐条核对译文，分类筛选，保存即写回 |
| 替换工具 | `bat\replace_tool.bat` | 输入词 → 看命中 → 批量替换，自动备份 |
| 待处理清单 | `bat\make_checklist.bat` | 列出「保守处理/拿不准/没处理」的行 |

三者只读写 `3_译文\`，不碰游戏文件；改完要跑一次 `build.py --no-gfx` 才进游戏。
首次保存会把整批译文快照写进 `3_译文\备份\`，进度存在 `3_译文\备份\待办进度.json`。

## 6. 常见故障

| 症状 | 先查什么 |
|---|---|
| `paths.py` 有 `·` | `project.json` 的 `dirs` 键缺失或指错；新游戏照 `project.example.json` 抄 |
| `缺少配置文件 config.json` | 复制 `config.example.json` 到**游戏文件夹**并填 key |
| `engine_tool 指向的文件不存在` | 相对路径按游戏文件夹解析；推荐 `..\工具\engine\EscudeTools.exe` |
| 译名前后不一致 | 词表里没有该词，或该词长度超过 12 被跳过（`load_terms` 的限制） |
| 游戏里出现 `?` | 用字不在码表且 SJIS 编不了 → 跑全量构建重算 |
| 中文整片消失 | 误用了 `--no-gfx` 且解包树字库未汉化 → 跑一次全量构建 |
| 回封没产物 | `-e` 的输入必须是 `script.db` **文件**，不是目录 |
| 覆盖补丁时整机卡顿 | 游戏还在运行；覆盖前必须退出游戏 |

## 7. 这一层最容易踩的两个认知坑

1. **「改完看不到效果」先用回读校验**：从成品包里把数据解出来、按码表反查字节，确认是「没写进去」还是「写进去了但没显示」。后者才需要动字库。
2. **索引用指令参数，不要用计数器**。指令参数会跳号，计数器会整段错位。

更多症状与根因见 [`04-踩坑与FAQ.md`](04-踩坑与FAQ.md)。
