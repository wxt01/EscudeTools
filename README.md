# Escu:de 引擎 Galgame 汉化工具包

面向 **Escu:de 系 ADV 引擎**（`ESC-ARC2` 封包 / `@mess` 脚本 / 位图字库）的中文汉化工具。

> 本目录**只有工具、脚本、文档、模板**。
> 不含游戏本体、游戏资源、译文、字库图、补丁成品，也不含任何获取途径。

---

## 一、这套工具能做什么（两条路线）

| 路线 | 处理什么 | 接手文档 |
|---|---|---|
| **文本汉化** | 对话、选项、人名、系统/UI 文本（改 `script.bin` / `data.bin`） | [`docs/01-文本汉化-接手.md`](docs/01-文本汉化-接手.md) |
| **图片汉化** | 烧在 PNG 里的界面文字（标题按钮、设置页、确认框、木牌等，改 `gfx.bin`） | [`docs/02-图片汉化-接手.md`](docs/02-图片汉化-接手.md) |

**两条路线互相独立，可以只做一条。** 大多数作品只需要文本路线；只有当界面文字直接画在图里、改数据库无效时，才动图片路线。

中文显示的核心方案是「**SJIS 冷门字符占位 + 重绘位图字库**」：不改 exe、不装系统字体、不写注册表，随时可完整还原。

## 二、工具包结构

```
工具\                        ← 本目录，可整包拷走/发布
├── README.md                本文件（总览，不展开细节）
├── scripts\                 ★ 唯一代码真源：准备/构建/翻译/注入/质检/字库/工具
├── bat\                     Windows 双击入口（拖一个游戏文件夹上去即可）
├── docs\                    接手文档 01~05（见「文档路由」）
├── ui_image_toolkit\        图片汉化子管线（脚本 + 方法论 + 示例）
│   ├── _work.py             工作区解析（所有 config_*.py 共用）
│   ├── config_* / build_* / verify_* / compare_*    每批图一组四件套
│   ├── examples\menu_button_单图\                    第一批示例（含 layout/inspect）
│   └── 汉化方法与思路.md    ★ 规范版方法论（深挖才读）
├── tools\汉化待办.exe        逐条核对译文的图形工具（预编译）
├── engine\                  ★ 解包器固定位置（第三方，**不随仓库发布**）
├── config.example.json      翻译后端模板（复制到游戏文件夹后填 key）
├── project.example.json     项目配置模板（复制到游戏文件夹）
└── glossary/characters/*.example.tsv   术语表与角色语气表模板
```

`engine\` 里的解包器**不从仓库分发**，来源与编译方法见 [`vendor/README.md`](vendor/README.md)。

## 三、游戏文件夹的标准骨架（每个游戏一个文件夹）

工具本身不含数据；每个游戏在 `游戏\<游戏名>\` 下一个自包含文件夹，结构固定：

```
游戏\<游戏名>\
├── project.json      唯一配置（引擎路径、各段目录、字体、数据库表名）
├── config.json       API 与翻译参数（只在本机，不入库）
├── 00_现状.md        一页纸：进度、译名定稿、未做项、常用命令
├── names_zh.json     人名表 → 写进 data.bin
├── ui_zh.json        界面文本 → 写进 data.bin
├── 0_原版\           原版 *.bin（只读）
├── 1_解包\           output\{script,data,gfx}
├── 2_日文文本\       导出日文 json（按剧情顺序）
├── 3_译文\           译文 jsonl
│   ├── 词典\         glossary.tsv / characters.tsv / terms_*.tsv
│   └── 备份\         译文快照 + 待办进度.json
├── 4_底版\           干净底版：script.db / db_*.db / gfx\font\ja_jp / gfx\sys
├── 5_构建\           中间产物 cmap\ pages\（可随时删，重建即得）
├── 6_补丁\           三个 bin + 使用说明.txt
├── 7_图片\           图片汉化工作区（待做原图/待交付/工作输出/…）
└── 8_测试\           test_game\ 本地测试目录
```

新建游戏时照抄这个骨架（或跑 `prepare.py` 自动建）。删一个游戏文件夹 = 干净清空一个项目。

## 四、30 秒上手

```bat
:: 1) 解包器放好（只需一次）
::    从 vendor/README.md 拿到 EscudeTools.exe，放进 工具\engine\

:: 2) 建游戏文件夹
::    新建 游戏\你的游戏\，复制 project.example.json 为 project.json，
::    填 game_dir 与 engine_tool

:: 3) 一键准备（备份 → 解包 → 解脚本 → 提取 → 干净底版）
python scripts\prepare.py --project 游戏\你的游戏

:: 4) 翻译（复制 config.example.json 为配置后填 api_key）
python scripts\hx.py translate 游戏\你的游戏\2_日文文本 游戏\你的游戏\3_译文

:: 5) 构建补丁
python scripts\build.py --project 游戏\你的游戏
```

产物在 `6_补丁\`：`script.bin`、`gfx.bin`、`data.bin`，拖进游戏目录覆盖即可。

改译文后只重打脚本：`python scripts\build.py --project 游戏\你的游戏 --no-gfx`
（前提是解包树里的字库页已经是汉化版；脚本会先检查并拦住误操作。）

## 五、文档路由

**AI 接手只读三份**（合计约 10 分钟）：

1. 桌面 `EscudeTools_结构改造与接手说明.md` —— 结构变成什么样、名字怎么变的、哪些事不能做
2. **本 README** —— 工具能做什么、怎么起手
3. `游戏\<游戏名>\00_现状.md` —— 这个游戏做到哪一步

**其余文档都是「动手时读」，不是接手必读。** 一次全读只会把口径读串。

| 文档 | 什么时候读 |
|---|---|
| `docs/01-文本汉化-接手.md` | 要真跑一遍文本流程（命令顺序、产物、验收） |
| `docs/02-图片汉化-接手.md` | 要真做界面图（先判型，再选自动化或精修） |
| `docs/03-引擎技术笔记.md` | 要动封包 / 脚本 / 字库公式 |
| `docs/04-踩坑与FAQ.md` | 出了症状，查根因 |
| `docs/05-工程决策与试错记录.md` | 想知道「为什么这么设计」「哪些路走不通」 |
| `ui_image_toolkit/汉化方法与思路.md` | 图片路线完整方法论（46 条错误总表） |

`_归档\` 里的旧文档（改造前的 docs 01/02/05/07 等）**不要读**，口径已过期。

## 六、边界

- **图片内文字**：只对「底色能无损重建」的图有效（纯色 / 竖向渐变）。高光、水彩笔触、金箔底上的字，自动化会破坏质感——保留原文比做坏强。
- **视频字幕**：OP/ED 需听译压制，不在范围内。
- **语音**：原音，不配音。
- **引擎硬编码提示**：写在 exe 里的弹窗无法改。
