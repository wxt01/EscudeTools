# Escu:de 引擎 Galgame 汉化工具链

面向 **Escu:de 系 ADV 引擎**（`ESC-ARC2` 封包 / `@mess` 脚本 / 位图字库）的中文汉化工具合集。

从解包、解脚本、提取、翻译、质检、注入、回封，到**不改 exe 的中文显示方案**（位图字库重绘）、界面文本、界面图片处理，以及两个面向非技术使用者的图形化工具，全部在这一套里。

> 本仓库**只包含工具、脚本与文档**。
> 不含任何游戏本体、游戏资源、脚本数据、译文文本、字库图、补丁成品，也不提供任何下载链接。

---

## 一、它解决什么问题

这类引擎的中文汉化有三个坎，本工具链分别给了做法：

| 坎 | 具体表现 | 本工具链的做法 |
|---|---|---|
| **编码** | 引擎按 Shift-JIS 读文本，中文写进去会变问号或断字 | 中文先映射成 SJIS 里的**冷门汉字占位符**，引擎以为在显示日文 |
| **字形** | 引擎**不调用系统字体**，文字是从 PNG 图册里按格贴图 | 把中文字形**画进原字库的对应格子**，重新封回 `gfx.bin` |
| **对位** | 格子怎么算、占位符该落在哪一格，错了就整片错字或空白 | 从引擎自身代码推出取字公式，按公式生成，见 `docs/03-引擎技术笔记.md` |

**关键结论：全程不改 exe、不装系统字体、不写注册表。** 只替换资源包，随时可完整还原。

## 二、覆盖的环节

```
① 备份          原版 *.bin 先存一份
② 解包          ESC-ARC2 → 脚本 / 数据库 / 图像
③ 解脚本        脚本 → SQLite（台词、指令、说话人）
④ 提取          按剧情顺序导出 日文 JSON / 逐行对应
⑤ 翻译          术语译前锁定 + 上下文 + 批量并发 + 断点续跑
⑥ 质检          残留日文 / 空译 / 长度溢出 / 标记丢失
⑦ 注入          译文写回 SQLite（可选码表映射）
⑧ 字库          码表 → 重绘各字号字库页
⑨ 回封          脚本 → 数据库 → 整包
⑩ 发布          三个资源包 + 使用说明，拖进游戏目录即用
```

外加两个给非技术使用者的小工具：

- **汉化待办（GUI）**：把待核对的行按「未译 / 成人向 / 拟声词 / 超长 / 残留日文」分类，一条条过，保存即写回译文
- **替换工具（CLI）**：输入一个词 → 显示命中处与原句 → 输入替换词 → 批量替换，自动备份

## 四、快速开始

### 0. 环境

- Windows 10/11
- Python 3.10+（`tkinter`、`pillow`、`numpy`、`fonttools`）
- .NET 8 运行时（仅当自行编译引擎工具时需要）
- 一个日文原版游戏目录（自备，本仓库不提供）

```bat
pip install pillow numpy fonttools
```

### 1. 准备引擎工具

见 `vendor/README.md`。需要一个能解 `ESC-ARC2` 的命令行工具（解包 / 解脚本 / 回封 / 重打包），
把它的路径填进 `project.json` 的 `engine_tool`。

### 2. 建项目

```bat
mkdir myproject
copy project.example.json myproject\project.json
:: 编辑 project.json，填 engine_tool 与 game_dir
```

### 3. 一键准备

```bat
python scripts\prepare.py --project myproject
```

产出：

```
myproject\
├── 0_backup\        原版 bin 备份
├── 1_unpack\        output\ （script\ / data\ / gfx\）
├── 2_json_jp\       每脚本一个 JSON，按剧情顺序
├── 3_json_cn\       译文（空目录，等翻译）
└── 4_pristine\      干净底版：script.db、db_*.db、gfx\font\ja_jp、gfx\sys
```

### 4. 配置翻译后端并开翻

```bat
copy config.example.json scripts\config.json
:: 填 api_key / endpoint / model
python scripts\hx.py translate myproject\2_json_jp myproject\3_json_cn
```

术语表放在 `scripts\glossary.tsv`（或 `config.json` 里改路径）。
翻译前会**锁定专有名词**（替换成占位符），译后还原，模型全程看不到原词。

### 5. 构建补丁

```bat
python scripts\build.py --project myproject
```

产出 `myproject\6_release\`：`script.bin`、`gfx.bin`、`data.bin`，拖进游戏目录覆盖即可。

改译文后只重出脚本（快）：

```bat
python scripts\build.py --project myproject --no-gfx
```

| 工具 | 入口 | 用途 |

## 六、技术路线为什么是这样

三条常见路线，本工具链选第三条：

| 路线 | 做法 | 问题 |
|---|---|---|
| A 改编码 | 改 exe 的字符集判断 + 扩字符类型表 + 改索引换算 | 要打多处补丁，漏一处就断字；exe 若有完整性校验会启动失败 |
| B 装字体 | 生成映射 TTF + 替换系统字体 | 本引擎**不读系统字体**，这条路无效 |
| **C 位图字库** | 中文 → SJIS 冷门字符 → 重绘字库页对应格子 | 不动程序、不动系统，风险最低；代价是要批量画图 |

C 路线的两份关键推导（取字公式、页/格边界）在 `docs/03-引擎技术笔记.md`，
其中包括一个**必须避开**的坑：引擎只渲染正文实际用到的那批页，画到更后面的页会显示空白。

## 七、已知限制

- **图片内文字**：标题画面按钮、存读档大标题、部分 UI 底图、CG 内嵌字、STAFF 图 —— 文字直接烧在带水彩笔触/金箔纹理的图里，自动重绘会破坏原画质感，本工具链只对「底色可无损重建」的图有效（见 `docs/05`）
- **视频字幕**：OP/ED 需听译 + 压制，不在范围内
- **字体观感**：位图字库由系统字体渲染，字重/字距与其他汉化补丁自建的字库有差异
- **语音**：仍为原音，不做配音
- **引擎硬编码提示**：写在程序里的弹窗文本无法通过资源包修改
